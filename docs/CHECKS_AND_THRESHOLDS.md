# 检查与阈值说明

这份文档回答两个问题：**每项检查为什么这么查**，以及**每个阈值为什么是这个数**。

写它的原因是：平台会替人做"这张切片能不能用"的决定，而这些决定最终落在几十个数字上。
如果不写清楚每个数字的来历，使用的人就无法判断该不该信任某条结论，也无法在换数据集时知道要调哪个。

## 0 · 怎么读这份文档

每个阈值都标了依据等级，这是全文最重要的约定：

| 标记 | 含义 |
|---|---|
| **客观** | 不需要阈值，判据是事实（文件在不在、能不能解码） |
| **物理** | 从成像物理或数据规格推出来的（nm、体素尺寸、chunk 网格） |
| **自适应** | 不是固定值，从数据本身算出来（本 block 的中位数、本 block 的期望相关性） |
| **经验** | **我按经验定的，没有用人工标注校准过**。换数据集可能要调 |

必须说在前面：**16 项检查里的阈值，大部分是"经验"级**。当初做验证时验的是"能不能检出缺陷"，不是"阈值定在哪里"。
在 mouse_30um 这份真实数据上，真正改变过结论的只有 3 项检查，其余要么从未触发，要么只产生最低等级的提示。
第 9 节有一张完整的可信度总表。

## 1 · 判定链条

一张切片从像素到"能不能用"，中间经过五道转换：

```
像素 → 每项检查各给一个分数 [0,1]
     → 分数对照该检查的四档阈值，得到严重度 none/low/medium/high/critical
     → 该切片取最坏的一档；低于 high 且读取正常且所在 block 没有 block 级失败 → 通过
     → 通过数 ÷ 总数 = 留存率
     → 留存率 + critical 数量 → block 等级 A/B/C/D
```

**分数一律定义成"1 是好、0 是坏"**，而不是"缺陷强度"。这样所有检查可比，综合分可以直接取最小值。

**综合分取最小值而不是平均值**，因为质量由最差的一项决定。一张切片如果裂了，其他十五项都满分也不能用；
取平均会把这个致命问题稀释成 0.94。

## 2 · 共用底座

三样东西被所有检查共用，先讲清楚它们，后面每项检查才好说。

### 2.1 统计量：全分辨率图只存在一瞬间

`ingest` 阶段每张切片解码一次，算出约 20 个统计量和两张缩略图，然后**立刻丢掉原图**。
之后所有检查只看统计量和缩略图。这个设计决定了内存占用与数据集大小无关，只与一个 block 组的 tile 数有关。

关键统计量：

| 名称 | 定义 | 谁在用 |
|---|---|---|
| `mean` | 有效像素平均灰度，归一化到 [0,1] | 亮度突变 |
| `std` | 有效像素灰度标准差 | 空白、对比度漂移 |
| `sharpness` | 拉普拉斯方差 ÷ 灰度方差 | 严重模糊 |
| `frac_mode` | 出现最多的那个灰度值占比 | 空白 |
| `frac_low_sat` / `frac_high_sat` | 触底 / 触顶像素比例 | 饱和 |
| `frac_fill` 等 | 填充值连通域的面积、形状、包围盒 | 裂缝 |

**为什么锐度要除以方差**：拉普拉斯方差衡量高频能量，但它同时受对比度影响——
同样清晰的两张图，对比度高的那张拉普拉斯方差也高。除以灰度方差之后，剩下的才是"清晰程度"本身。

**为什么统计量只在有效像素上算**：先找出恰好等于填充值（默认 0）的连通域，把它们排除再算。
不这样做的话，一张带裂缝的切片会同时被判成模糊（黑区没有纹理）、亮度突变（均值被拉低）、饱和（大量 0 值像素）。
这是实际发生过的问题：加了填充值感知之后，同一张切片从四条告警变成一条。

### 2.2 参考链：防止一处缺陷级联成一串误报

序列检查要和"上一张"比。但如果上一张本身是坏的，这一张就会被误判，然后它又成为下一张的坏参考，一路传下去。

解决办法分两层。

**第一层，谁有资格当参考。** 通过了切片级检查的切片才进入参考链。
取消资格的六种情况是：缺失、损坏、空白、严重模糊、饱和、裂缝。
注意区分：**所有切片都被评估，但只有链上的切片能当基准**。一张坏切片照样会被打分，只是不会污染别人。

**第二层，两步回退。** 比较时用链上前一张；如果前一张被任何序列检查判为异常（各检查共享同一个异常集合），
就改用再前一张；两张都异常就重置，这张记 `reference_reset` 不给分。

这样一处缺陷最多影响后面两张。这个规则是在实测中加上的——早期版本里一张坏切片会导致后面十几张全部报警。

### 2.3 序列比对：高通 + 相位相关

两张切片要比较，先各自做三步预处理：

1. **高通滤波**：减去高斯模糊版本，滤掉比约 128 nm 更粗的结构。
   依据 **物理**。要去掉的是染色不均、电子剂量波动这类低频差异，它们在切片间天然不同，留着会淹没真正的结构差异。
   128 nm 大约是几个突触间隙的尺度，比它粗的基本不是组织结构。没有体素尺寸时退化为固定 2 像素——这是 **经验** 级兜底。
2. **归一化**成单位向量，此后两张图的点积直接就是相关系数。
3. **相位相关**求整数位移：两图傅里叶变换相乘取共轭、除以模长、逆变换，峰值位置就是位移。
   按位移对齐后在重叠区算归一化互相关，得到"对齐后相关性"。

比较在约 **32 nm/像素** 的尺度上做。依据 **物理**：太细则噪声主导且慢，太粗则看不见局部错位。
长边不超过 512 像素、短边不少于 48 像素是 **经验** 级的上下限保护。

**期望相关性函数**：从本 block 自己的间隔 1、间隔 2 的相关性中位数，外推出任意间隔的期望值。
依据 **自适应**。这一步很重要——不同数据集、不同脑区的相邻切片相似度差别很大，用固定值当基准必然误判。
而且跳过若干张之后的比较也有了合理基准，不会因为间隔大就被当成跳变。

## 3 · 切片级 10 项检查

### 3.1 缺失切片 `missing_slice`

**为什么查**：z 序列里少了一张，后续所有按 z 索引的操作都会错位。

**怎么查**：该 z 没有文件、或 precomputed 里没有任何 chunk。

**阈值**：无，命中即 0 分。依据 **客观**。

**真实数据**：mouse_30um 上 0 例。

### 3.2 损坏切片 `corrupt_slice`

**为什么查**：文件在但读不出来，或者尺寸和数据集对不上。后者尤其隐蔽——尺寸不一致的切片会让所有空间坐标失效。

**怎么查**：解码抛异常，或解码后的形状与数据集声明的形状不符。

**阈值**：无，命中即 0 分。依据 **客观**。

**真实数据**：0 例。

### 3.3 空白切片 `blank_slice`

**为什么查**：整张几乎没有信息——成像失败、切片掉了、或者导出时写了一张空图。

**怎么查**：取两个信号的**最小值**。
信号一 `std / 0.02`：灰度变化够不够。
信号二：众数占比从 0.8 开始的线性下降斜坡，也就是"是不是绝大多数像素都是同一个值"。

**为什么要两个信号**：只看 std 会漏掉"有噪声但没结构"的情况；只看众数会漏掉"渐变但无内容"的情况。
取最小值意味着**任一信号判空白就算空白**。

**阈值**：`std_ref = 0.02`（归一化灰度），`mode_frac_start = 0.8`。依据 **经验**。

**真实数据**：400 张里 4 张 critical（z8 那张真空白），其余 396 张分数全部 ≥0.99。
分布是明显的双峰，阈值落在中间的空谷里——**这意味着阈值怎么挪都不改变结论，是这 16 项里最稳的一项**。

### 3.4 严重模糊 `severe_blur`

**为什么查**：离焦、漂移、电子束不稳都会让切片失去高频细节。模糊的切片训不出边界。

**怎么查**：该切片锐度 ÷ **本 block 所有切片锐度的中位数**。

**为什么用相对值**：不同数据集的绝对锐度差好几个数量级（取决于体素尺寸、染色、成像模式），
固定的绝对阈值换个数据集就没意义。用本地中位数当基准，问的是"这张比同批的典型切片糊多少"。

**代价**：整个 block 均匀模糊时，所有比值都是 1.0，全部满分通过。**这是这项检查当前最大的缺陷**，
需要补一个绝对锐度下限作为兜底。

**阈值**：四档 `0.75 / 0.55 / 0.35 / 0.2`，比默认档收紧；另加**绝对下限** `absolute_floor = 0.02`，
最终分数取"相对本 block"与"相对绝对下限"两者的较小值。依据 **经验**。

**绝对下限是 2026-09-14 补的**，专门解决上面那个"整块均匀模糊全部满分"的盲区：
只要绝对锐度低于 0.02，无论本 block 的中位数是多少都会扣分。

**真实数据**：产生 48 条告警，**全部是 low，一条都没到影响判定的程度**，最低分 0.578。
也就是说这项检查在这份数据上从未改变过任何一张切片的去留。

### 3.5 饱和 `saturation`

**为什么查**：触顶或触底的像素没有信息，通常是曝光设置问题。大面积饱和的区域是训练噪声。

**怎么查**：（触底像素比例 + 触顶像素比例）÷ 0.20，并从预览图上圈出饱和区域的包围盒。

**阈值**：`frac_ref = 0.20`。依据 **经验**。含义是"两成像素饱和就判到 0 分"。

**真实数据**：7 条，最低分 0.52。没有真饱和样本可以检验，所以这项**实现了但未验证**。

### 3.6 裂缝 / 未成像区域 `crack`

**为什么查**：切片制备会产生裂缝和褶皱；对齐或拼接会留下没有数据的区域。
两者在导出时都是成片的填充值（通常 0），但**对训练的意义完全不同**——
裂缝两侧的组织发生了错位，而未成像区域只是没有数据。

**怎么查**：找填充值的连通域，按**最大连通域的形状**分三类：

| 判据 | 归类 | 含义 |
|---|---|---|
| 贴着图像边缘 且 面积 ≥15% 且 主轴比 <6 | `no_coverage` | 组织没填满画布，采集或拼接问题 |
| 主轴比 ≥3 | `crack` | 狭长的带状，裂缝或褶皱 |
| 其余 | `missing_region` | 内部成块缺数据 |

**为什么用主轴比**：裂缝是细长的，用连通域的协方差矩阵特征值之比（长轴方差 ÷ 短轴方差的平方根）衡量细长程度。
未成像区域通常是贴边的大块。

**这条规则是 2026-09-14 改过的**。旧规则是"主轴比 ≥3 **或** 跨度 ≥0.5 记 crack"，那个"或"导致
任何占了半张图的大块都被叫成裂缝。在 mouse_30um 上，22 处未成像区域被误判成裂缝，
四个 block 的"主要问题"全部指向 crack，任何据此排查的人都会走错方向。
真实情况是那些黑区边界是**直线加规则台阶，台阶高约 16 像素**，正是采集时的 tile 网格。

**阈值**：面积 `area_ref = 0.02` 起扣分、`area_full = 0.60` 扣到 0 分，**两者之间按对数递减**；
`min_frac = 0.002`（小于这个比例忽略）、`elongation_crack = 3.0`、
`no_coverage_min_frac = 0.15`、`no_coverage_max_elong = 6.0`。依据全部 **经验**。
四档 `0.9 / 0.7 / 0.5 / 0.2`，比默认档敏感，因为无数据区域的危害是确定的。

**2026-09-14 修好的一个缺陷**：旧版用线性刻度、分母 0.05，意味着**面积一超过 5% 分数就饱和到 0**。
当时 49 条 finding 里有 43 条面积 ≥5%，实际面积从 6.2% 一直到 93.8%，但严重度完全相同——
一块占 6% 的边角和几乎整张没有数据的切片在系统里等价。
改成对数刻度后：面积 2.8% 得 0.897 分（low），93.8% 得 0 分（critical），中间有了梯度。

**真实数据**：这是**当前唯一真正在决定数据去留的检查**——52 张未通过的切片里，44 张是它单独判死的。

### 3.7 亮度突变 `brightness_jump`

**为什么查**：相邻切片平均灰度突然变化，说明成像条件变了（电子剂量、探测器增益、染色批次）。
突变处的切片与前后不可比，会干扰需要 z 方向一致性的模型。

**怎么查**：与参考切片的平均灰度之差 ÷ 0.2。参考切片按参考链的两步回退规则选。
被判为 high 及以上的切片会被标记为异常，从而不再当后续切片的参考。

**阈值**：`jump_ref = 0.2`（归一化灰度）。依据 **经验**。
换算一下：low 档对应差值 0.05，也就是 **12.8 个灰阶**（8 位图）。

**真实数据**：81 条告警，其中 63 条落在 12.8–20 灰阶之间。
EM 切片间的染色与剂量波动本来就在这个量级，所以这 63 条多半是正常起伏。
但它确实单独判死了 3 张（最大差值 52 灰阶），所以不能简单关掉。
**建议把 low 档放宽到差值 0.08 左右**，既保留真正的突变又去掉四分之三的噪声。

### 3.8 对比度漂移 `contrast_drift`

**为什么查**：整个序列的对比度随 z 缓慢变化，会让模型在序列两端表现不一致。

**怎么查**：该切片灰度标准差相对本 block 中位数的 **log2 偏移**，除以 1.0。
用 log2 而不是比值，是因为"对比度翻倍"和"对比度减半"应该等价地严重。

**两个层面**（block 级是 2026-09-14 补的）：

- **切片级**：单张相对本 block 中位数的偏差，`log2_ref = 1.0`（对比度差一倍时得 0 分）
- **block 级**：标准差随 z 的 log2 斜率，`trend_ref_per_100z = 0.5`（每 100 层变 1.41 倍时得 0 分），
  要求至少 8 张切片且线性拟合的 R² ≥ 0.5（散乱的起伏不算趋势）

旧版只有切片级，测的是**偏差**不是**漂移**——逐张偏差都不大、但从头到尾一路变化的情况检不出来。
现在 block 级补上了这一块。

**block 级告警上限是 MEDIUM**，不会判整个 block 失败：对比度整体漂移是提示，
不像"切片间互不相关"那样让数据不可用。依据 **经验**。

**真实数据**：最低分 0.848，**从未触发**。351 张被评估（其余 49 张不在参考链里所以跳过）。

### 3.9 charging artifact `charging_artifact`

**为什么查**：电荷积累是 EM 特有的缺陷。电子束打在不导电的区域上，电荷积累会造成沿扫描方向的亮暗条带，
以及局部的亮度斜坡。这类切片的灰度不可信，也会干扰后续的亮度一致性判断。

**怎么查**：三个信号取最小值，每个都**相对本 block 的典型值**判断。

| 信号 | 怎么算 | 为什么 |
|---|---|---|
| 行列条带 | 行均值（和列均值）剖面相对自身中值滤波基线的最大偏离 | 这是 charging 最主要的表现：整行或整列偏亮 |
| 频谱各向异性 | 傅里叶幅度谱按角度分 12 个区间，最强方向的能量占比相对均匀分布超出多少 | 细密条纹在频域是方向性的能量集中 |
| 亮度斜坡 | 整幅拟合一个平面 `z = a·y + b·x + c`，取跨越整幅的总落差 | 电荷积累造成的渐变 |

**为什么要相对本 block**：这是全文最重要的一条经验。见第 9 节的实测反例——用绝对阈值时，
真实 EM 本身的照明梯度（中位 0.176）就超过了按合成数据定的阈值（0.30 配合下移的档位），
400 张里报了 213 张。改成"扣掉本 block 的中位数与 3 倍 MAD 之后还剩多少"，降到 35 张。

**阈值**：`band_ref = 0.10`、`anisotropy_ref = 0.20`、`ramp_ref = 0.15`（都是扣除基线后的超出量），
基线用 `k_mad = 3.0`，各信号的最小离散度分别是 0.01 / 0.02 / 0.02（防止 MAD 为 0 时过敏）。
四档回到默认 `0.75/0.6/0.4/0.2`。依据 **合成标定 + 真实数据修正**。

**真实数据**：mouse_30um 上 35 条。

### 3.10 污染 `contamination`

**为什么查**：切片表面的灰尘、冰晶、碎屑。它们遮住底下的组织，是确定的训练噪声。

**怎么查**：两个条件**同时**满足才算——灰度极端，**并且内部平坦**。

具体是：先用中位数加 3.5 倍 MAD 定出"极端"像素；再算每个像素 3×3 邻域的标准差，
取最平坦的 15% 作为"平坦"；两者取交集后做形态学开运算，只保留 12 像素以上的连通块。

**为什么必须加"平坦"这一条**：只看灰度极端会把线粒体、髓鞘这类深色组织当成污染。
实测证据：只用极端判据时，128 张合成数据里误报 76 张（中位分数 0.730，低于 low 阈值）。
加上平坦度之后误报归零——**组织再深也有纹理，污染斑块内部是平的**，这是两者的本质区别。

**阈值**：`sigma_k = 3.5`（多少倍 MAD 算极端）、`flat_quantile = 0.15`（多平才算平）、
`min_blob_px = 12`（太小的是噪点）、`area_ref = 0.02`（面积除以它得分数）、
`max_blob_frac = 0.25`（超过这个比例说明整幅都异常，那是对比度问题不是污染，不报）。依据 **合成标定**。

**真实数据**：mouse_30um 上 0 条。**这项是实现了但未验证**——可能这份数据确实干净，
也可能判据偏严，需要有人看图确认（见 `docs/OPEN_QUESTIONS.md` 的 B4）。


## 4 · 序列级 6 项检查

### 4.1 切片跳变 `slice_jump`

**为什么查**：相邻切片内容突然不连续——连续缺了好几张、组织撕裂、或者根本不是同一块样品。

**怎么查**：对齐后相关性 ÷ **该 z 间隔的期望相关性**。

**为什么要除以期望值**：这是这项设计最关键的地方。如果中间缺了两张，间隔变成 3，
相关性自然会低，用固定阈值必然误判。期望值从本 block 自己的数据外推，所以间隔多大都有合理基准。

**block 级判定**：如果整个 block 相邻切片的相关性中位数低于 0.15 且链长至少 4，
说明这批切片在分析尺度上根本互不相关，这时发**一条 block 级告警**并跳过所有逐切片的序列检查，
而不是给每张都打上标记。这避免了"整体有问题"被表达成"每一张都有问题"。

**阈值**：`min_median_ncc = 0.15`（block 级判定线），四档 `0.6 / 0.45 / 0.3 / 0.15`。依据 **经验**。
四档比默认宽松，因为相关性本来就有较大自然波动。

**真实数据**：7 条，其中 4 条 critical，且与空白切片 z8 重合——那里确实是内容断裂。判断合理。

### 4.2 全局错位 `global_misalignment`

**为什么查**：相邻切片整体平移没对齐，说明配准失败。

**怎么查**：相位相关得到的整体平移量，与阈值比。

**阈值**：有体素尺寸时 **200 nm**，依据 **物理**——大约是一个突触间隙的尺度，
超过这个量级的错位会让跨切片的结构追踪失败。
没有体素尺寸时退化为**名义 tile 短边的 5%**，依据 **经验**。

两个跳过条件：z 间隔超过 3 跳过（隔太远的切片组织本来就移位了），
相关性低于期望值一半时跳过并标记为异常（那是跳变不是错位，两者要分开）。

**真实数据**：从未触发。但结论的性质在 2026-09-14 变了。

旧版相位相关只给整数个缩略图像素，一个缩略图像素等于 4 个全分辨率像素，
所以**小于 4 px 的位移一律测不到**，99 个相邻对全是 0.00——那时无法区分"数据对齐得好"和"检查测不出来"。

加了抛物线亚像素拟合之后，同样 99 个对测到：中位 0.08 px、最大 0.39 px（全分辨率）。
**现在"从未触发"是一个测量结论**：这份数据确实是亚像素对齐的，远在 13 px 的判定线之下。

### 4.3 局部错位 `local_misalignment`

**为什么查**：整体对齐了但局部扭曲——组织在切片过程中发生了不均匀位移。

**怎么查**：把序列缩略图切成 4×4 网格，每格单独做相位相关，
算各格位移**相对全局位移的残差**的中位数。用中位数而不是最大值，是为了不被单个纹理差的格子带偏。

纹理太弱的格子（标准差低于阈值）和相关峰太低的格子会被剔除，剩不到 3 格就跳过整张。

**阈值**：有体素尺寸时残差上限 **150 nm**（依据 **物理**，比全局错位严格，因为局部形变危害更大），
否则名义 tile 短边的 3%（**经验**）。网格 4×4、每格至少 32 像素、容差 1 个缩略图像素、
z 间隔上限 2、相关性门槛 `gate_frac = 0.25`。依据均为 **经验**。

**门槛从 0.5 降到 0.25 是有原因的**：错位本身就会降低整体相关性，用和"跳变"一样的门槛
等于把自己要找的东西挡在外面。实测中一个半幅 20 px 的错位就被门槛挡掉、只报成了跳变。
逐格的 `min_peak` 才是真正保证"这一格对得上"的判据。

**边界 tile 的修正**：阈值用**名义** tile 短边而不是裁剪后的实际短边。
否则一个 200 像素宽的边缘 tile 会得到 5 倍严格的阈值，把正常的 12 像素位移判成 critical。

**真实数据**：同全局错位，恒为 1.0，从未触发。
而且 `max_gap = 2` 的限制让它在这份数据上几乎不可能触发——
缺陷附近的切片，其参考往往在 2 张以外。

### 4.4 z-order 错误 `z_order_error`

**为什么查**：切片顺序错乱——重复采集、相邻两张调换、某张放错位置。
顺序错了的数据训练出的模型会学到错误的 z 方向连续性。

**怎么查**：三种模式分别判。

**重复**：与前一张相关性 ≥0.985 且位移几乎为零。
阈值 0.985 很高，依据 **经验**——真正的重复应该接近 1.0，留一点余量给压缩噪声。

**互换**：判据是两个条件同时成立——"前一张和后一张更像（超过当前张）"且"当前张和后两张更像"。
这是一个"弱-强-弱"的链接模式：如果 A、B 被调换了，那么原本相邻的对会变成隔位对。
两边都要满足才判，是为了避免单边巧合。

**错位**：相邻两张彼此更像，而当前张与某张**非相邻**切片高度匹配。
命中后会在整条链上搜索它最像哪一张，把那个 z 记录下来。

**阈值**：`duplicate_ncc = 0.985`、`margin = 0.03`（两个条件都要超出的余量）、
`swap_ref = 0.10`、`odd_ref = 0.15`、`match_frac = 0.8`。依据全部 **经验**。

**真实数据**：从未触发，恒为 1.0。逻辑在合成数据上验证过（注入的重复和互换都检出了），
但在真实数据上未经检验。

### 4.5 局部形变 `local_deformation`

**为什么查**：切片内部的非刚性形变。平移配准纠正不了它，而它会让跨切片的结构追踪出错。

**怎么查**：这一项和 4.3、4.6 **共用同一次计算**——把序列缩略图切成 4×4 网格，每格单独做相位相关，
得到一个逐格位移场。然后：

- 4.3 局部错位看的是：各格位移相对**全局平移**的残差
- 4.6 section deformation 看的是：位移场拟合出的**仿射变换**里的拉伸与剪切
- 4.5（本项）看的是：**扣掉仿射之后还剩下的残差**，也就是真正非刚性的部分

三项一次计算、三种读法，这样既不重复算，语义也分得开：平移不是形变，均匀拉伸是整片形变，剩下的才是局部形变。

**阈值**：残差上限 `max_residual_nm = 120`（比局部错位的 150 nm 更严，因为非刚性形变危害更大），
无体素尺寸时退化为名义 tile 短边的 2%。要求至少 3×3 网格、6 个有纹理的格子。
四档是 `0.93/0.88/0.78/0.6`，明显高于默认。依据 **合成标定**。

**为什么四档要抬这么高**：合成数据上，注入的非刚性扭曲得 0.813 分，最差的干净切片是 0.971，
**中间只隔 0.158**——这是四项新检查里区分度最差的。档位不抬上去就抓不住，抬上去则对干净数据容忍度变小。
**这项的可信度最低**，真实数据上报的 38 条需要人工核对。

### 4.6 section deformation `section_deformation`

**为什么查**：整张切片相对参考切片的拉伸、压缩、剪切。这是切片制备时的机械形变（刀具、展平、贴片）。

**怎么查**：用 4.5 里那个逐格位移场，拟合仿射变换 `d = A·(归一化坐标) + t`。
`A` 的对称部分携带缩放与剪切，反对称部分是旋转。取缩放与剪切分量里最大的那个作为"应变"，
即**跨越半个视野累积的相对位移**。纯平移和纯旋转不计入——它们不是形变。

**两个必须做的修正**：

1. **相对本 block 判断**。相邻切片的组织结构本来就在变，这种变化在位移场上看起来和真形变很像。
   实测：干净切片也能量到 0.02–0.05 的应变。所以改成扣掉本 block 的中位应变与 3 倍 MAD。
2. **最小 3×3 网格**。仿射拟合每个方向有 3 个未知数，2×2 的 4 个点等于在拟合噪声。
   实测证据：允许 2×2 时，128 张合成数据里误报 16 张。

**阈值**：`strain_ref = 0.03`（扣除基线后的超出量）、`k_mad = 3.0`、`min_spread = 0.004`。
四档 `0.7/0.55/0.4/0.2`。依据 **合成标定**（注入的仿射形变得 0.0，最差干净切片 0.726）。

**遗留问题**：整个 block 均匀形变时检不出来——这是"相对本 block"这一族设计的共同盲区，
和严重模糊一样（见第 9 节）。


## 5 · 全局判定

### 5.1 严重度四档

```
分数 ≥ low       → none
low > 分数 ≥ medium   → low
medium > 分数 ≥ high  → medium
high > 分数 ≥ critical → high
分数 < critical        → critical
```

默认四档 `0.75 / 0.6 / 0.4 / 0.2`。依据 **经验**。
三项检查有自己的覆盖值：严重模糊 `0.75/0.55/0.35/0.2`、裂缝 `0.9/0.7/0.5/0.2`、切片跳变 `0.6/0.45/0.3/0.15`。

覆盖的理由：裂缝的危害确定所以更敏感；相关性的自然波动大所以更宽松。这两个判断本身也是 **经验** 级。

### 5.2 通过规则

三个条件同时成立才算通过：读取正常、最坏严重度**低于 high**、所在 block 没有 block 级失败。

**为什么门槛画在 high**：low 和 medium 表示"有瑕疵但可用"，high 表示"这张的问题会影响下游"。
这条线直接决定留存率，是整个平台最重要的一个判断。依据 **经验**。

**继承的缺陷**：由于裂缝分数在 5% 面积就饱和，一张只有 5% 未成像的切片和一张 90% 没有数据的切片
都是 critical，都不通过。前者其实还有 95% 的可用区域。

### 5.3 留存率与等级

留存率 = 通过数 ÷ 总数。

```
留存率 < 0.6 或有 block 级失败  → D
留存率 ≥ 0.95 且无 critical 切片 → A
留存率 ≥ 0.85                  → B
其余                           → C
```

依据 **经验**，而且是相当随意的经验——0.85 和 0.95 这两条线没有任何数据支撑。
mouse_30um 的四个 block 留存率是 85%、88%、86%、89%，恰好全部落在 B 档，这纯属巧合。

数据集等级用同样规则算在全部切片上，但**只要有任何一个 D 级 block，数据集等级最高只能是 B**。

## 6 · 标签验证的 7 项检查

这一组回答"标签能不能用来训练"，逐层把标签卷和 EM 对照。

### 6.1 形状不匹配 `shape_mismatch`

**为什么查**：标签平面必须能对应到 EM 平面，否则每个像素的位置都是错的。

**怎么查**：标签平面必须是 EM 平面的**整数倍**缩放，且 x、y 倍数相同。
比 EM 更细的掩码（例如 mip0 的 4096² 对 mip1 的 2048²）会等距抽样到 EM 网格。

**阈值**：无。依据 **客观**。不匹配直接判 fail 并**跳过逐层读取**——对不上的资产读了也没意义。

### 6.2 层数不匹配 `z_count_mismatch`

**为什么查**：层数不同意味着 z 对应关系未知，不能猜。

**阈值**：必须完全相等。依据 **客观**。

**真实数据**：mouse_30um 的 `delete/` 六个掩码里有五个是 750 层对 100 张 EM，全部判 fail。
平台不猜这个映射——这只能由数据方给出。

### 6.3 标签缺失 `label_missing`

EM 这一层存在，标签没有对应文件。**客观**。

### 6.4 标签为空 `label_empty`

**为什么查**：标签文件在但全是背景，而 EM 这一层有内容，说明标注漏做了。

**阈值**：背景占比 ≥ **99.9%**。依据 **经验**。

**真实数据**：**从未触发**。因为这份分割几乎每个像素都有 id，背景占比中位数是 0。
这项检查对这份数据天然无效。

### 6.5 有标签无图像 `label_without_image`

**为什么查**：反过来的情况——EM 这一层缺失、损坏或空白，标签却有内容。
这类标签是凭空来的，不能信。

**阈值**：前景占比 > **1%**。依据 **经验**。

### 6.6 标签画在填充区 `label_in_fill`

**为什么查**：**这是这组里最有价值的一项**。标签画在了 EM 根本没有成像的地方。
这种数据拿去训练，会教模型在空白区域也输出结构。

**怎么查**：取 EM 的填充值区域，看标签前景中有多少比例落在里面。

**阈值**：> **2%**。依据 **经验**，但事后看这个值选得好——
真实数据上这个指标的分布有明显断层（80 分位是 0，90 分位是 0.15），
阈值落在断层里，**怎么挪都是同样那 16 层**。

**真实数据**：mouse_30um 的 GT 有 16 层命中。

### 6.7 编码不一致 `encoding_inconsistent`

各层解码出的数据类型不同，说明导出过程有问题。**客观**。

### 6.8 标签冲突 `label_conflict`（跨资产）

**为什么查**：多个本该互斥的类别掩码（如轴突、树突、胞体）之间不该有重叠像素。

**怎么查**：逐层数被多个掩码同时认领的像素比例。

**阈值**：冲突比例 ≥ 0.1% 报 warn。依据 **经验**。

## 7 · patch 生成的验收阈值

采样窗口先过一道 QC 过滤：窗口内**每一张**切片都必须通过 QC。然后按类型验收。

| 类型 | 验收条件 | 依据 | 真实数据上是否起作用 |
|---|---|---|---|
| 分割 | 前景 ≥30% 且至少 2 个 id | 经验 | **完全失效**：前景恒为 1.0，id 数最小 4 |
| 膜 | 边界像素占比 ≥2% | 经验 | 有效，实测最小 0.022 恰在阈值附近 |
| 突触 / 线粒体 | 掩码占比 ≥0.2% | 经验 | 有效，是它限制了产量（只拿到 29/64） |
| 困难负样本 | 预测与 GT 不一致度 ≥5% | 经验 | 未验证（没有预测） |
| 校对候选 | 不设门槛，取不一致度最高的前 n 个 | — | 未验证 |
| 失败样本 | QC finding 严重度 ≥ low | 经验 | 有效 |

**分割的两条验收等于没有**。要 64 个给 64 个，不是因为筛得准，是因为根本没筛掉任何窗口。
真正起过滤作用的只有前面的 QC 窗口条件。

**一个必须知道的实质限制**：窗口要求连续 dz 张全部通过 QC。实测不同 dz 的存活率：

| dz | 合格窗口 / 全部窗口 |
|---|---|
| 2 | 305 / 396（77%） |
| 8 | 153 / 372（41%） |
| 16 | 47 / 340（14%） |
| 32 | **0 / 276（0%）** |

逐张看有 87% 合格，但缺陷散布均匀，四个 block 的最长连续合格段只有 14、27、28、27 张。
**这份数据训不了 dz≥32 的 3D 模型**，不是数据少，是没有足够长的干净段。

## 8 · patch 集合的泄漏检查

这组的性质和前面都不同：它**验证构造的正确性**，而不是过滤数据。

**四项硬检查**（任一非零则集合判定不通过）：

| 检查 | 含义 |
|---|---|
| 重复 | 同一个包围盒出现两次 |
| 跨折重叠 | 不同折（训练/验证/测试）的 patch 在体积上重叠，最严重的泄漏 |
| 越出 block | patch 没有完全落在所属 block 内 |
| 折不一致 | patch 的折与其所属 block 的折对不上 |

**三项软信号**（报告但不判死）：近重复（三维 IoU ≥0.9）、未划分块内的 patch、跨折相邻块对。

**必须说清楚**：四项硬检查在当前设计下**天然为零**。
因为划分是按 block 做的、patch 不跨 block，跨折重叠在构造上就不可能发生。
所以它们真正的作用是在将来有人手工传入坐标、或者划分逻辑被改动时充当护栏，
而不是现在在筛掉什么东西。报告"全部通过"时应该这样理解。

**近重复用 IoU 有局限**：IoU 对"同一位置不同 z"的窗口不敏感，内容哈希会更合适。

### 一条必须记住的实测教训：合成标定不能替代真实数据

这是这份文档里最重要的一段。

我用合成缺陷给 charging 标定了阈值：注入缺陷的切片得 0.348 分，最差的干净切片 0.604 分，
档位定在两者之间（low = 0.50）。在合成数据上完美工作。

**换到 mouse_30um 上，400 张报了 213 张。**

原因：主导信号是"亮度斜坡"，而真实 EM 本来就有轻微的照明梯度（实测中位 0.176），
超过了我按合成数据定的阈值 0.30。合成数据没有这层背景梯度，所以标定时看不出来。

改成"相对本 block 的典型值判断"之后降到 35 张。

**结论**：合成标定只能验证"检测器能不能工作"，不能确定"阈值定在哪"。
现在 16 项里 6 项用了相对本 block 的自适应设计（严重模糊、对比度漂移、切片跳变、charging、两项形变），
这类不怕跨数据集迁移；**其余 10 项仍是绝对阈值，没有一项经过人工标注校准**。

### 自适应设计的共同盲区

"相对本 block"解决了迁移问题，但带来一个统一的盲区：**整块均匀异常一律检不出来**。
整个 block 都模糊，每张的相对分数都是 1.0，全部满分通过。

目前只有严重模糊补了绝对下限作为兜底，其余五项还没有。**每一项的兜底判据是什么，需要逐个想清楚。**

## 10 · 怎么改阈值

**单次运行临时覆盖**（不改代码，适合试验）：

```bash
curl -X POST http://127.0.0.1:8765/api/v1/qc/runs -H 'Content-Type: application/json' -d '{
  "dataset_id": "mouse_30um",
  "config": {
    "thresholds": {"brightness_jump": {"low": 0.6}},
    "params": {"crack": {"area_ref": 0.3}}
  }
}'
```

覆盖值会存进该次运行的 `config_json`，所以**任何一次运行都能查到它当时用的是什么阈值**。

**永久修改**：改对应检查类的 `default_params` / `default_thresholds`。改完要重跑，不会追溯已有结果。

**建议的校准方法**：目前所有"经验"级阈值都缺少校准。可行的做法是人工标注几十张处于边界的切片
（"这张算不算模糊""这个亮度差算不算突变"），然后反推每项检查的四档分位。
按现在的情况，最值得先校准的是亮度突变和严重模糊这两项——它们产生的告警量最大，而信噪比最低。
