# 待确认问题清单

截至 2026-09-14。按**谁能回答**分组，每组是一份完整的问题单，不用读全项目就能回答。
每条都写了：问题、为什么要问、不解决会怎样、需要什么形式的答案。

一句话背景：平台已经能跑通"登记 → 图像质检 → 出训练样本"的全链路，16 项检查全部实现。
但下面这些问题不解决，质检结论的可信度和训练样本的完整性都会打折。

---

# A 组 · 需要数据方回答（10 条）

这组成本最低、解锁最多。多数问题回答一句话即可。

## A1. mouse_30um 和 human_30um 的体素尺寸是多少纳米？

**为什么要问**：16 项检查里有 4 项用物理阈值（全局错位 200 nm、局部错位 150 nm、局部形变 120 nm、
序列比对尺度 32 nm/像素）。没有体素尺寸，这些全部退化成"图像宽度的百分之几"。

**不解决会怎样**：按我们推测的 14.6 nm/px 折算，现在的错位判定比设计值宽松约 7 倍。
**mouse_30um 当前的等级结论就是在这套宽松阈值下得出的。**

**需要的答案**：`xy = ? nm，z = ? nm`。两个数字。

## A2. `delete/` 目录是什么？

**现状**：里面六个子目录（axon、cellbody、dendrites、synapse、vesicle、synapse+vesicle），
每个 750 张 4096×4096 的调色板 PNG，像素值是 0–10 或 0–50 的小整数。

**为什么要问**：目录名叫 delete，我们不敢当标注用，也不敢删。

**需要的答案**：这是要删除的中间产物，还是可用的类别标注？如果是标注，里面的小整数分别代表什么？

## A3. 750 张标注怎么对应 100 张 EM？

**现状**：`delete/` 里六个掩码有五个是 750 层，EM 是 100 张。平台判定为"层数不匹配"并拒绝使用，
因为这个映射只能由数据方给出，我们不猜。

**不解决会怎样**：**突触和线粒体两类训练样本完全生成不出来**，七类里少两类。

**需要的答案**：`s000..s749` 与 `im0000..im0099` 的对应规则。例如"每 7.5 层对应 1 张"，
或者"只有 s000..s099 对应，其余是别的区域"。

## A4. `seg/mip1` 的分割编码规则是什么？背景 id 是哪个值？

**现状**：RGB 三通道 PNG，我们按 `id = R<<16 | G<<8 | B` 解出 3872 个 id。
值为 0 的像素几乎只出现在 EM 没有成像的地方——也就是说这份分割里"背景"约等于"未成像"，
而不是细胞外空间。

**不解决会怎样**：分割训练样本的验收条件"前景占比 ≥30%"完全失效（实测前景恒为 1.0），
等于没有筛选。

**需要的答案**：确认 RGB 打包方式对不对；背景 / 未标注区域用哪个值表示。

## A5. mouse_30um 有 12 张切片成片区域没有数据，是什么原因？

**现状**：z2、z4、z7、z9 等 12 张切片上有大面积零值区，占比 14% 到 84%。
边界是**直线加规则台阶，台阶高约 16 像素**，正好是采集时的 tile 网格。

我们最初误判成"裂缝"，核对预览图后确认不是——裂缝不会是这个形状。现在归类为"未成像区域"。

**为什么要问**：成因决定该怎么处理。对齐后转出视野的话，原始数据里可能还有；
拼接漏 tile 的话，可以补采或补拼。

**需要的答案**：这是对齐后移出画布、拼接漏了 tile、还是采集时就没扫到？

## A6. 元信息四项：脑区、染色方法、成像模式、采集批次

**现状**：mouse_30um 只填了物种和批次，human_30um 六项全空。

**为什么要问**：这四项是需求明确列出的数据集元信息，也是将来做跨数据集泛化分析的分组依据。

**需要的答案**：每个数据集四个字段的值。

## A7. `seg/mip0` 是空目录，是故意的吗？

**现状**：`seg/mip1` 到 `mip4` 都有 100 张，`mip0` 是空的。

**需要的答案**：mip0 没导出，还是本来就没有？

## A8. EM 只有 mip1 起，没有 mip0，原始分辨率是哪一层？

**现状**：`em/mip1` 是 2048²×100，`mip2`–`mip4` 是它的降采样。没有 `mip0`。

**为什么要问**：影响我们对体素尺寸的推断，也影响 patch 能出到多细。

**需要的答案**：mip1 就是原始分辨率，还是 mip0 存在于别处？

## A9. `allen_mouse` 和 `rat_100_100_100um` 的目录约定是什么？

**现状**：这两个数据集扫描时报"找不到 EM 卷"，因为目录结构和默认约定不同：

| 数据集 | EM 目录 | 分割目录 | 备注 |
|---|---|---|---|
| allen_mouse | `EM/`（内有 `em_mouseA.vsvi`、`mip2`、`mip3`） | `seg/` | 没有 mip0/mip1 |
| rat_100_100_100um | `EM_img/`（内有 `IARPA_JWR15.vsvi`、`layer23_v185`、`mip0`–`mip2`） | `seg/` | 多了一个 `layer23_v185` |

**需要的答案**：哪一层是要用的 EM？`.vsvi` 文件是索引还是别的东西？
`layer23_v185` 是另一个版本还是子区域？

## A10. `Toy_datasets` 下面是四个公开基准（EMNeuron、cremi、lucchi、snemi），要不要接入？

**为什么要问**：这四个是公开基准数据集，有现成的 GT，**很适合用来校准我们的检查阈值**（见 B 组）。
但它们的目录结构各不相同（例如 cremi 下面还分 `corrected` 和 `orig`）。

**需要的答案**：要不要接？如果要，优先哪一个？

# B 组 · 需要懂 EM 的人看图判断（4 条）

这组是**校准**，不是问答。需要一个能判断"这张图有没有问题"的人，估计半天到一天。

## B1. 为什么必须做这件事：我刚刚证明了阈值不能跨数据集迁移

这是这轮工作里最重要的一个发现，也是这组请求的全部理由。

我用合成缺陷给 charging artifact 检查标定了阈值：注入缺陷的切片得 0.348 分，最差的干净切片 0.604 分，
档位定在两者之间。在合成数据上完美工作。

**拿到 mouse_30um 上，400 张里报了 213 张。**

查下来主导信号是"亮度斜坡"：真实 EM 本来就有轻微的照明梯度，中位数 0.176，
而我按合成数据定的阈值是 0.30，配上下移的档位就全线触发。

我把它改成"相对本 block 的典型值判断"之后降到 35 张。但这件事说明：
**用合成数据标定的绝对阈值，在真实数据上可能错一个数量级。**

现在 16 项检查里，6 项是相对本 block 的自适应设计（不怕迁移），
**10 项仍是绝对阈值**：缺失、损坏、空白、饱和、裂缝、亮度突变、污染、局部错位、全局错位、z-order。
这 10 项没有一项用人工标注校准过。

## B2. 标注一批边界样本（主要请求）

**需要判断的**：约 50–100 张处于边界的切片，每张做一个二选一的判断：

- 这张算不算"严重模糊"？
- 这个亮度差算不算"突变"？（当前实测：81 条告警里 63 条的差值在 12.8–20 灰阶之间，
  这正是 EM 染色和剂量的正常波动范围，我怀疑大部分是噪声）
- 这块无数据区域算"裂缝"还是"未成像"？

**我会准备什么**：从现有数据里挑出边界样本，做一个左右对比的界面，点"是/否"即可。出题由我做。

**产出**：能反推出每项检查四档阈值该定在哪，让"经验值"变成"标定值"。

## B3. 两项形变检查报出来的东西是真的吗？

**现状**：新实现的 section deformation 报了 23 条，local deformation 报了 38 条。

**问题**：我无法判断这些是真的形变还是估计噪声。合成数据上，注入的非刚性扭曲得 0.813 分，
最差的干净切片是 0.971，**中间只隔 0.158**——这是四项新检查里区分度最差的。

**需要判断的**：看十几张报出来的预览图，给个"确实变形了 / 看不出来"。

## B4. 污染检查在真实数据上一条都没报，是数据干净还是判据太严？

**现状**：污染检查在 mouse_30um 上零告警。可能这份数据确实没有污染，
也可能我要求"灰度极端**且内部平坦**"这个判据太严。

**需要判断的**：这份数据里有没有肉眼可见的灰尘、冰晶、碎屑。有的话给我几个 z 值。

# C 组 · 需要项目层面决策（7 条）

## C1. 要不要投入 B 组的人工标注？

**成本**：一个懂 EM 的人半天到一天。
**收益**：10 项绝对阈值从"经验值"变成"标定值"，质检结论才谈得上可信。
**不做的后果**：平台能跑，但每个结论后面都得跟一句"阈值未经校准"。

这是我认为当前**投入产出比最高**的一件事。

## C2. mouse_30um 有一个 block 从 B 降到了 C，要不要通知下游？

**原因**：新实现的四项检查多抓到了一些问题，其中一个 block 的留存率降到 83%。

**问题**：这是"更准确"还是"更严格"？我倾向于更准确——原来 12 项看不见的东西现在看得见了。
但如果已经有人拿 B 级这个结论在用，口径变化需要提前说明。

## C3. 大数据集要不要跑？机器时间怎么安排？

allen_mouse 421 GB、rat 2.6 TB。按服务器本地读的实测速度，单机跑完一轮质检约需一到七天。

**需要决定**：跑不跑、什么时候跑、能不能长时间占用服务器。

## C4. 要不要上多机？

如果要处理上面两个数据集，单机时间不可接受的话需要多机方案（Ray）。
但我实测过一个前提：**这条流水线是 I/O 密集的**，单个 block 92% 的时间在读取和解码，
CPU 只用到 1.76 核。所以多机加速的上限是各节点到存储的聚合读带宽，不是核数。
上多机之前，单机先把解码并行化能拿到几倍，改动只在一个函数里。

**需要决定**：先做单机优化，还是直接上多机。

## C5. 服务器防火墙要不要放行？

平台已部署在 `<工作站>:<数据根目录>/deploy/`，开机自启。
但服务器只对外开放 22 端口，同事现在需要建 SSH 隧道才能访问。

**需要管理员执行一条命令**（需要 sudo）：

```bash
sudo ufw allow in on tailscale0 to any port 8788 proto tcp comment 'EM QC platform'
```

放行后直接访问 http://<服务器地址>:8788 。

## C6. 平台没有登录认证，要不要加？

现状：能连上端口的人都能操作。我已经关掉了删除数据文件的功能（删不掉原始数据），
但任何人都能启动运行、删除数据库里的记录。

**需要决定**：维持现状（内部小范围用）、加一个共享令牌、还是接入统一认证。

## C7. 第 4 步起需要模型预测，谁提供？

路线图第 4 步（分割质检）之后的每一步都以"存在模型预测"为输入。目前没有。

**影响**：七类训练样本里的困难负样本和校对候选两类生成不出来；
分割质检、突触质检、评测框架都无法开始。

**可以先这样**：用现有 GT 当替身预测把流程和接口跑通，之后换真模型。
**需要决定**：谁来提供第一个能出预测的分割模型，什么时候。

# D 组 · 我自己还没想清楚的（3 条，供讨论）

这组不是问别人要答案，是我认为设计上还有模糊之处，写出来避免被当成已解决。

## D1. 形变检查分不清"切片被拉伸"和"组织换了一层"

我用相邻切片的逐格位移场拟合仿射变换来测形变。但相邻切片的组织结构本来就在变，
这种变化在位移场上看起来和真的形变很像。

**现在的做法**：相对本 block 的典型值判断——整体的组织变化形成一条基线，只有明显超出基线的才算形变。
**遗留问题**：整个 block 均匀形变时检不出来。

## D2. "相对本 block"这个设计有共同盲区

现在 6 项检查用这个模式。好处是不怕跨数据集迁移，坏处是**整块均匀异常一律检不出来**：
整个 block 都模糊，每张的相对分数都是 1.0，全部满分通过。

我给模糊加了绝对下限作为兜底，但其余五项还没有。**需要想清楚每一项的兜底判据是什么。**

## D3. 这份数据训不了大的 3D 模型，该怎么办

实测：逐张看有 86% 合格，但缺陷散布均匀，最长的连续干净段只有 14 到 28 张。
连续 32 张全合格的窗口是**零个**。

**选项**：接受只做 2D 或小 dz 的模型；放宽质检标准让更多切片通过；
或重新选择具有足够连续有效切片的数据。这需要和算法侧一起定。当前平台已移除切片损坏修补功能。
