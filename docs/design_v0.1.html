EM Image QC v0.1 架构与检测设计

连续切片电镜数据的注册、逐 block 自动质检与算法侧取数。本文描述系统怎么切分 block，16 项切片级与序列级检查各自怎么判定，以及 block 如何按问题分级。所有规则均对应 em-qc-platform 当前代码，实测数字来自 mouse_30um。

1目标与边界

输入是 project_terminal/<project>/datasets/datasets/<dataset_id>/ 下的原始 EM 图像栈及其伴随资产（GT 分割、模型预测、突触与细胞器预测、骨架、agent 执行记录）。系统要回答三个问题：这批数据有什么问题、问题在哪一张切片的哪个位置、哪些 block 可以直接喂给训练。

  • 每张切片输出 16 个检查的分数、failure type、严重度、坐标和预览；每个 block 输出聚合分数、留存率、等级、最长连续可用段和主要问题类型。
  • 不重切、不落盘。QC 只保存缩略图和数字；算法侧需要像素时按坐标从源卷即时读取，每一次取数写入 serve_log。
  • 小数据集整体作为训练数据；大数据集抽一部分 block 作训练样本，整卷进推理清单（需求原文）。怎么抽是实现决策，已定为按等级分层，见第 8 节。分类阈值默认 2×10⁹ 体素，也可在 dataset.json 里直接指定。
  • v0.1 单机顺序执行，不做分布式；persist 阶段按 run 与 block 幂等写入，后续把 block 分发到多机时不需要改存储层。

2总体架构

代码分层与图中方块一一对应：emqc/registry（readers、manifest、scanner）、emqc/qc（base、slice_checks、serial_checks、stages、runner、preview）、emqc/db（models）、emqc/api（datasets / qc / data / traces 路由与 Jinja2 看板）。

3block 的定义与划分

block 是 QC 与训练采样的基本单元：连续 100 张切片 × 一个 1024×1024 的 XY tile。这两个数是本项目 .env 的配置（EMQC_BLOCK_SIZE_Z=100，EMQC_BLOCK_SIZE_XY=1024），代码内置默认是 64 张 × 整张平面。平面两个方向都不超过 1024 时整张作一个 tile；任一方向超过就按 1024 切。id 编码 z 范围与 tile 原点：z00000-00099_y01024_x00000；整张平面时省略 tile 后缀。

为什么按 tile 而不是整张平面判定。真实数据里裂缝往往只穿过一部分区域：mouse_30um 的 z6 在 y1024_x0 这个 tile 是 missing_region，在其他三个 tile 却是干净的。整张判定会把整张切片一起拉黑，按 tile 判定让另外三块 1024² 仍然可用。代价是穿过 tile 边界的同一条裂缝会被相邻 tile 各记一次。

4五阶段流水线

ingest 阶段产出的统计量

每张切片：mean, std, min, max, p1, p50, p99, frac_low_sat, frac_high_sat, frac_mode, entropy_bits, lapvar, sharpness，以及填充区域指标 frac_fill, n_fill_components, fill_largest_frac, fill_bbox, fill_elongation, fill_span。像素数超过 4×10⁶ 时按整数步长子采样后再算。填充区域指"无数据"像素（默认 0，dataset.json 的 em.fill_value 可改）的 8 连通域；找出它们之后，亮度、对比度、清晰度只在有效像素上计算，裂缝切片因此不会同时被判成模糊和亮度突变。

5分数、严重度与坐标

  • 分数：每项已实现检查对每张切片给 quality score ∈ [0, 1]，1 为完美。未实现的检查（stub）写 null，不影响通过判定，但在结果里可见，避免"没查"被当成"没问题"。
  • 严重度由分数按阈值映射，默认 ≥0.75 none · <0.75 low · <0.6 medium · <0.4 high · <0.2 critical；个别检查有自己的阈值（下表列出），也可在 QCConfig.thresholds 覆盖。
  • finding：严重度 ≥ low 就写一条 qc_findings，记录 check、failure type、严重度、分数、z、参考 z、坐标与数值证据。
  • 通过：passed = 状态 ok ∧ 最坏严重度 < high ∧ 所在 block 没有 ≥ high 的 block 级 finding；留存率 = 通过切片数 / 切片数。
  • 切片综合分 = 已实现检查分数的最小值（一个致命缺陷就足以让切片不可用），缺失 / 损坏切片记 0；block 综合分 = 切片综合分均值（block 级 finding ≥ high 时再与该 finding 的分数取最小）；数据集综合分 = 按切片数加权的 block 均值。
  • 坐标：z 为数据集内 0 起的索引，z_abs = z + z_offset；bbox = [x0, y0, x1, y1] 为全分辨率、数据集像素系、右开区间，tile 内检出的框会加上 tile 原点回写；序列检查带参考切片 z_to，错位类带 shift {dx, dy}。
  • 预览：只对严重度 ≥ medium 的切片存缩略图（长边 ≤ 256 px），每个 block 存一张拼图；任意切片可通过 /api/v1/data/{ds}/preview/z/{z}.png 即时生成。

真实数据里的裂缝长什么样

第一版把这些切片判成了饱和 + 模糊 + 亮度突变三项：黑带把均值拉低、把 Laplacian 方差压小、又把 0 值像素比例推高。把填充区域从统计量里剔除后，同一批切片 high 以上只剩 crack 一项，failure type 与实际成因一致。

7序列级检查（stage serial_qc）

比较尺度与参考链

序列检查不在原始分辨率上比：切片先按体素尺寸块平均到约 32 nm/px（长边 ≤ 512 px，短边 ≥ 48 px，两者冲突时保证短边；没有体素尺寸时退化为长边 256 px），高通滤除粗于 128 nm 的结构，归一化后做整数相位相关，再在重叠区算对齐后的相关系数 NCC。期望相关性用 block 自己估：expected(1) = m₁ = median NCC(gap 1)（限制在 [0.05, 0.999]），expected(2) = m₂ = median NCC(gap 2)（不超过 m₁），更远按几何外推 expected(g) = m₂·(m₂/m₁)^(g−2)；block 内没有 gap-2 配对时退化为 m₁^g。

8block 分级与训练划分

等级规则对训练的含义
A留存率 ≥ 95% 且没有 critical 切片（缺失 / 损坏计为 critical）整块直接采样
B留存率 ≥ 85%按 slice_passed 掩码跳过坏片采样
C留存率 ≥ 60%可入选训练样本（默认份额 20%），只能在 longest_clean_run 允许的短 z 窗口内采样
D留存率 < 60%，或有 ≥ high 的 block 级 finding不进训练；需重新采集或修复

训练 / 推理划分

需求：小数据集整体用于训练；大数据集的 sample 用于训练、完整卷用于推理。实现决策（2026-09-12 确定）：大数据集的 sample 按等级分层抽取，让训练集既有干净 block 也有"可用但有瑕疵"的 block，避免模型只见过最容易的数据。

  • 小数据集所有 block 标 train。
  • 大数据集抽 EMQC_TRAIN_SAMPLE_BLOCKS（默认 8）个 block 标 train_sample，各等级份额 EMQC_TRAIN_SAMPLE_STRATA（默认 A 50%、B 30%、C 20%），层内按固定种子随机抽取，可复现；某一层数量不足时配额顺延到下一层；D 级永不入选。其余 block 标 inference。block 在第一次 QC 之前是 unassigned。
  • 抽样计划、实际选中的 block、种子写入 qc_runs.config_json.train_sampling，并随 GET /api/v1/data/training/manifest 一起输出。
  • POST /api/v1/data/{ds}/patches/sample 给出不跨 block 的随机 patch 坐标：默认要求 z 窗口内所有切片在该 tile 通过 QC（only_passed，可关），可加 min_quality；默认在数据集全部 block 里采样，传 split 或 block_ids 才限定范围。
  • 对照实验可切换 EMQC_TRAIN_SAMPLE_POLICY：best（只取最好）或 random_usable（A/B/C 内均匀随机）。

11已知限制与 v0.2

  1. 4 个 stub 需要算法：charging、contamination、local_deformation、section_deformation。表里已给出计划路线。
  2. 阈值是启发式初值。在合成缺陷集上 13 处可检测缺陷全部命中且无 high 以上误报，但真实数据的 brightness_jump 与 blur 大量 low 级告警说明默认阈值对真实亮度波动偏敏感，需要用人工标注回归。
  3. tile 拼接亮度不均（棋盘状明暗）在 mouse_30um 里很明显，目前只间接体现在 brightness_jump 上，建议增加专门的 tile_seam 光照不均检查。
  4. 序列检查是整数像素相位相关，分析尺度 32 nm；亚像素、小于分析尺度的错位检不出。
  5. 体素尺寸缺失时错位阈值退化为图像比例，跨数据集不可比；接入真实元信息后再校准。
  6. 部署位置：allen_mouse 421 GB、rat 2.6 TB 这类大数据集应把平台部署到数据所在的 <工作站>（64 核、372 GB 内存）上跑，Mac 只做控制台；QCRunner.process_group 是天然的分发单元。
