1系统分层架构

六层，自下而上。数据源对平台永远只读；所有落盘产物都在 var/ 之下。处理层现在有三个引擎：图像 QC、标签验证、Patch Factory。

2模块依赖

箭头方向是"依赖谁"。registry/fs 仍是最底层；Patch Factory 依赖 QC 引擎与接入层，不反向；所有路由只组合下层。

3MySQL 数据模型

18 张表分四域。实线是真实外键（级联删除），虚线是代码层面的软引用。

4MySQL 写入流程

七个动作，各自写入的表互不重叠。第 2 步按"运行 + block 先删后插"组织，重跑任一 block 幂等；第 4 步按资产先删后插，重验幂等。

5整体闭环

从发现数据到算法产出回写，八步成环。Patch Factory 插在 QC 划分之后、交付之前：它决定训练到底喂什么。

6QC 流水线五阶段

按 block 组执行。全分辨率图像只在第一阶段存在，读一张、算完、丢掉，内存占用与数据集大小无关。

7block 划分

block 是 QC、划分与 patch 采样的共同单元：连续 100 张切片乘一个 1024 见方的 XY tile。同一 z 段的所有 tile 一起处理，每张切片只解码一次。

8Patch Factory 内部

三道门，顺序固定：标签先过验证，block 先有划分，然后才生成集合；每个集合出门前跑一遍泄漏与重复检查。

9两条交付链路

训练侧读本地（分片或按 patch 集合切），推理侧不落盘。区别在于数据被读多少次、读完要不要留副本。

10单次运行的执行节点

控制台把一次运行展开成节点图：同一 z 段共享一次解码，然后每个 tile 各自走完后四个阶段。

12每个阶段算法缺什么

按 18 步路线图逐阶段列出：平台已有的基础、算法上缺的东西、依赖谁。前三个阶段来自代码审计，第 4 步起是尚未开工的部分，列的是必须补的算法与可复用的基础。

阶段 1 至 3 · 已建成，缺口是精度与覆盖

阶段状态已有基础算法上缺的依赖 / 来源
1 Dataset Registry结构完成本地与 SSH 同一套发现；大小分类；九类资产、版本、trace 表；标签卷一致性验证几乎无算法缺口。缺元信息自动抽取（从 precomputed info / 采集元数据读体素尺寸、脑区）；非标签资产（突触表、骨架 SWC、JSON 预测）的格式校验与解析数据方给体素尺寸、脑区、delete/ 含义
2 EM Image QC12 / 16五阶段流水线、参考链、物理尺度、三分类裂缝、分级与留存率四项未实现：charging（方向性条纹：频谱各向异性 + 局部亮度斜坡）、污染（高对比孤立团块：形态学 + 纹理异常）、局部形变（非刚性配准残差场：光流 / 弹性配准）、section deformation（整片仿射拟合：各向异性缩放与剪切）。已实现但弱：阈值未用人工标注标定（70% 告警为 low/medium）；相位相关只到整像素（需抛物线亚像素拟合）；序列检查不跨 z 段边界（需带一张参考切片）；模糊与对比度只相对本 block 归一化（需绝对锐度下限）；contrast_drift 测的是偏差不是趋势；local_misalign 在 max_gap 2 下几乎不触发（需按 gap 缩放阈值）；合成回归只注入 4 种缺陷（需 128 张全集）人工标注一批 low/medium 边界样本；scipy / skimage 即可，无外部模型
3 Patch Factory4 / 7 可出标签解码与验证、稳定划分、难度、七种生成器骨架、四硬三软检查、Training Data API标签语义：rgb24 分割无 0 值，背景 id 未知，前景占比恒为 1；mask 与 EM 一致性只查填充区，缺 GT 边界与 EM 边缘的对齐度（边界处梯度响应统计）；标签冲突只覆盖互斥掩码，缺同一分割内 id 跨断裂检测；难度只用 QC，缺基于标签的难度（小目标密度、边界密度、细突起占比）；近重复只用 IoU，缺内容哈希去重；划分缺相邻块间的空间缓冲带；synapse 只取掩码连通域，缺 pre/post 配对与极性；membrane 目标是 2D 边界，缺 3D affinity / 有向边界；hard_negative / proofreading 缺预测输入；proofreading 缺"人工校对价值"排序（目前只按不一致度）模型预测（阶段 4 前提）；数据方确认背景 id 与 delete/ 映射
