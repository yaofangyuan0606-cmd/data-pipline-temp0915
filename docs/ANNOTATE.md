# 切片标注（VAST 风格）

「种子分割」作为主要补标入口，按「选范围 → 标目标 → 确认填色」操作；绿色目标/红色排除种子自动触发 CPU 膜边界预览，只补空白，可精确撤销。边界尺度和手动预览收在「调整边界」中。SAM 默认折叠为备用入口，功能和历史标注保留。使用方法与限制见 [SEED_SEGMENTATION.md](SEED_SEGMENTATION.md)。

需要用 SAM 圈选并补充标签时，请看 [SAM 切片补标使用指南](SAM_USER_GUIDE.md)。

页面：独立的「切片标注」工作区（侧栏顶部与「数据清洗」切换）——`/annotate` 标注工作台（全宽，按 `?` 看快捷键）、`/annotate/compare` 前后对比与溯源、`/annotate/guide` 使用说明。数据源由 `EMQC_ANNOTATE_ROOT` 指定（可用 `EMQC_ANNOTATE_EXTRA_ROOTS` 以分号追加更多根目录），
该目录下每个含 `em.npy` 的子目录是一个数据块，H01 交付的 `blocks/h01/<block>/` 布局直接可用。

**选数据块：先选批次，再选块。** 工作台和前后对比页左上角是两个选择框：「批次」= 数据块所在的导入目录（和审核进度页、入库
同一个名字，由 `GET /blocks`、`/comparison-blocks` 每项的 `batch_id` 给出，列表按（批次, 块）排序）；「数据块」只列这一批，
同一个原始块切出来的 `<原始块>_yYYYY_xXXXX` 归在一组（组名 = 原始块），选项只写 `yYYYY_xXXXX`，完整名字在悬停提示里
（工作台把完整名字、尺寸和体素大小放在「数据块」框的悬停提示里，不再单独占一行）。跳到别的块（`?block=` 链接、对比页「下一张待审」、标记链接）都会先切到那个块所在的批次。代码在
`emqc/api/static/block_picker.js`，两页共用。

**新增一批数据：`scripts/cut_tiles.py`。** 在服务器上从交付区的原始块（1024²×100）切出 512² 的小块，放进一个新的导入目录
（= 新批次）。切法、存储顺序、`meta.json` 约定和现有批次 `h01-demo-v2` 完全一样（小块 `_yYYYY_xXXXX` = 原始块
`[YYYY:+512, XXXX:+512, :]`，C 顺序；`geometry.origin` 用原始块原点、偏移记在 `offset_in_parent`），并在 meta 里记下来源原始块的
`uid` 和它在各训练数据集里的划分（`parent_splits`，按数据集 id 记：同一原始块的小块必须进同一个划分）。脚本只新建、不改不删：
原始块只能写目录名；批次名、目标目录、小块名和平台能看到的所有数据块（含符号链接的导入目录、`--root` 给的根目录）、
标注工作目录、数据库里已有的块重名就拒绝。先写进 `var/datasets/.incoming-*`，每块和原始块逐字节核对、用平台自己的读法核对，
再把原件改名到 `var/datasets/<批次>`、确认导入目录的链接都指到原件，最后才把导入目录改名到 `var/annotation/<批次>`——
中途失败不会有东西出现在 `var/annotation` 里。先加 `--dry-run` 看计划。接进服务：`run.sh` 里加
`export EMQC_ANNOTATE_EXTRA_ROOTS=$T/var/annotation/<批次>`，再 `systemctl --user restart emqc-8792`。

**数据目录是只读的。** 页面写出的一切——`seg_edit.npy` 工作副本、`edits/` 逐次记录、`edits.jsonl` 摘要、`created_labels.json` 新建标签——都放在
`EMQC_ANNOTATE_WORKDIR`（默认平台的 `var/annotate/<block_id>/`），交付目录里一个字节都不会多。早期版本曾把这些写进数据目录，
打开数据块时会自动迁移到工作目录，已有的改动不会丢。

**显示方向以源数据集为准（2026-09 改）。** `fetch_train.py` 存下来的是 CloudVolume 的原生轴序，所以数组的第 0 维是
体数据的 **X**、第 1 维是 **Y**；一张切片是 `arr[:, :, z].T`，**转置之后再显示**。这样屏幕的横轴就是体数据的 X、纵轴是 Y，
和 Neuroglancer 里看到的同一块画面完全重合——改之前两者差一个转置，跳过去对不上。屏幕坐标 x 是列、y 是行，
服务端拿到后按 `plane[y, x]` 取值，写回磁盘时由 `Block._disk_idx` 换回 `(x, y)`。

这条改的只是**看**的方向：`em.npy` / `seg.npy` 一个字节都没动，`edits/*.npz` 里记的始终是磁盘下标，
用改之前的记录回放也照样还原。代价是 `visual/slices_em/*.png` 与屏幕差一个转置，不能再原样下发，
EM 层一律由 `em.npy` 现渲染。对比页的 EM、原始标签、工作副本及来源图也使用同一显示方向。

`visual/slices_seg_color/*.png` 不能当标签用：它是 EM 与哈希颜色的叠加图，同一个 id 的像素在图里有几千种颜色，
和 EM 灰度的相关系数 0.79，id 无法从颜色反推。标签只来自 `seg.npy`；页面上的着色由 id 哈希生成，与那套 PNG 不同。

## 三个核心功能怎么实现的

**叠加与并排**。EM 永远是底图，分割是上层。叠加视图：一个视窗，分割按透明度盖在 EM 上，可只画边界；
三种对比手段——透明度滑块（, . 步进）、**自动渐变**（G，分割在 EM 上周期性淡入淡出）、**对比滑块**（C，拖一条分界线，
左边纯 EM、右边叠加）、按住 Tab 临时隐藏分割。并排视图（V）：两个视窗，左边纯 EM、右边 EM+分割叠加（可切成只看分割），
缩放、平移、翻页完全同步，鼠标在一边时另一边同一位置画十字线，所有工具在两个视窗里都能用。
分割层只栅格化一次进离屏 canvas，透明度在绘制时用 globalAlpha 施加，所以拖滑块和渐变都不重算像素。
每个视窗是三层 canvas：EM 灰度、分割着色、选中与悬停高亮。分割不是直接传彩色图，而是把这一片出现的
id 重新编号成 0..k 的 uint16 索引图（PNG 的 R、G 通道各存一个字节）连同"索引→id"表一起下发；着色、吸色、
标签高亮在浏览器里对着索引图做；历史改动高亮通过只读接口获取该笔操作的像素蒙版。颜色由 id 的哈希决定，同一个神经元在任何一片、任何一次打开都是同一种颜色。
id 一律按字符串传——H01 的 id 超过 2^53，JSON 数字会丢精度。

**吸色 / 填色**。拾取工具（或标注工具下 Alt+点击）读光标下的索引查表得到 id，设为当前标签。填充工具对点到的
像素做 4 连通泛洪，把整个连通区域改成当前标签（Shift+点击改整片同 id）；浏览器先在索引图上本地泛洪立刻显示，
同时把 (z, x, y, new_id) 发给服务器，服务器在体数据上做同样的泛洪并落盘，返回后前端重新拉这一片校准。画笔 /
橡皮按半径涂抹，鼠标抬起时把整条轨迹一次发过去。画笔模式下**左键涂当前颜色（只补空白）、右键拖动擦、Ctrl/⌘+点击拾取颜色**（右键点一下不拖动是弹出菜单，见下文「右键菜单」），
改半径：按住 Tab 左右移动鼠标（鼠标）；**触控板**上按住键时 macOS 会忽略触控板移动（防误触），所以改成点一下 Tab 松开、再左右移动，单击或再按一次 Tab 结束、Esc 还原；[ ] 一格一格调。调半径时不会落笔。橡皮（右键拖动或 E 工具）**只擦当前颜色**的像素——压到邻居身上不会把邻居擦掉（接口 `paint` 的
`only_id`），所以擦之前得先拾取要擦的颜色。平移改用中键、空格+拖动或 H。

**修缮边缘**（R）。点一下标签块：跨过黑色细胞膜、溢到膜外的部分收回来，**停在膜的外侧**——膜本身算这个细胞的，留下（2026-09-25 按需求确认：停在膜外侧、点一个修一个、收回的像素变空白、只修当前这一片）。分三步：先在很黑的膜处把标签切开，贴边的薄片朝外接触的大多是亮胞质（漏进了邻居）就去掉；再把压在外沿黑膜上的一层剥开，好把膜外断下来、漏进邻居的小碎片分出来去掉；最后把剥掉的膜从本体出发沿暗像素并回来，最多 6 像素厚（`MEMBRANE_PX`，H01 上细胞膜约 3～6 像素，膜外侧紧挨着的 1 像素模糊边也算膜）。细胞里的黑色细胞器不管贴不贴边都留下，离外沿 10 像素左右以外的像素永远不动。只收缩不扩张，一笔记录（`kind: refine`，来源归"算法辅助"），Ctrl/⌘+Z 撤销；选中修缮工具后，其下方显示独立的「修缮灵敏度」滑块（默认 50%），无需展开 SAM。H01 演示块上的评测：31 处跨过膜、膜外还有一块的人为漏标，膜外的部分平均收回 84%（中位数 100%），压在膜上的部分平均留下 95%；38 个原本贴着膜的细胞平均只改 0.02% 的像素，细胞器像素一个没动。

**悬停高亮**。只高亮当前鼠标所在的四连通区域，同一标签在画面里其他不相连的位置不会一起亮。
第一块的黄色选框也只圈出点击位置所在的连通区域。

**合并**。工具 M，每两次点击为一对，固定保留第一块的颜色：先点 A、再点 B，B 变成 A 的标签和颜色；
选择立即清空，再点 C、D，D 变成 C 的标签和颜色。只改当前切片中第二次点击的四连通区域，其他不相连区域与其他切片不变。
界面不再提供方向和范围选择。保存期间暂停编辑，防止连点复用上一对的选择；成功、无变化或失败后都从新的一对开始。
Alt+点击可重选第一块；Esc、切换工具、切片或数据块会取消未完成的一对。Ctrl+Z 一次撤销一对。
已经具有相同标签的两块无需再改，点击后也清空选择。底层 `/merge` 接口仍保留整片/整块按标签合并供脚本使用。

**缩放与翻页**。工作台和前后对比页的滚轮都用于缩放，向上放大、向下缩小。翻片快捷键仅为 ↑/A 上一片、↓/Z 下一片，
也有滑块和"连播"（可调每秒张数）。浏览器缓存最近 24 片并预取前后各 3 片，翻页基本不等待。

切割、分离、智能填充和切片损坏扫描/插值修补已移除，对应按钮、算法与接口均不再提供。已有标注结果、历史记录、撤销和溯源继续可用，无需迁移数据。

## 大块填充（`W`）

给没标注的大细胞上色：点一下，按电镜上的膜找出整个细胞，先预览（橙色），确认后才写入（记录类型 `bigfill`，溯源归为
「算法辅助」）；「接着填上一片 / 下一片」把刚填好的细胞接到相邻一片，同样先预览。只填 `seg == 0` 的像素。
numpy + scipy，不用模型和 GPU。点一下时两套算法各算一遍，择优：

- 标记分水岭（`emqc/annotate/bigfill_ws.py`）：膜强度按分位数分 27 层，从点击处往上找到「再涨就从膜缺口漏到别的区域」
  之前的那一层当自己的种子，只隔着强膜才连得通的其他区域核心、以及已有标签当别人的种子，一起淹没，在膜的脊线上分界；
- 随机游走（`emqc/annotate/bigfill.py`）：局部膜强度 → 点击处和其他区域的内部核心作种子、已有标签整块作别人的种子
  → 随机游走；窗口随细胞放大（256 → 512 → 整片），点到细胞器时改用包住它的胞质，经膜缺口连到隔壁时判为漏并退回严格结果。

分水岭在旁边小细胞都标好时更准，但挡漏几乎全靠这些标签，一片里没什么标注时会一下填满大半片；所以分水岭的结果是空的、
或比随机游走的大出一半以上（`FALLBACK_RATIO = 1.5`）就用随机游走的。传播（接着填上 / 下一片）只用随机游走
（上一片区域内缩 8 像素当种子），两套在传播上持平。两套在两个线程里同时算：4 核笔记本上 512² 的片一次约 0.5–1.5 秒，
1024² 的约 3–5 秒、分水岭峰值内存约 160 MB。同时最多算两个；同一个人又点了一下，还在排队或计算中的那次自己停下；
排队超过 10 秒返回 429。

为什么不用 SAM：SAM 按「像不像一个物体」逐片出掩膜，对很大、质地均匀、只靠细长膜隔开的细胞常常只圈一部分或选中
细胞器；删掉的旧「智能填充」固定只在点击点周围 256×256 里算，大细胞天然被截断。

测评（H01 四个 512² 块，每片把所有 ≥3000 像素的细胞一起抹掉当作「一大片没标」，在每个 ≥6000 像素的细胞最深处点击
还原，和原始分割比）。参数和择优规则只在 z 5/25/45/65/85（111 个细胞）上调；下表是没参与调参的 z 15/35/55/75/95
（122 个细胞，其中 21 个 ≥2 万像素）：

| 方法 | 点 1 下 IoU | 点 3 下 IoU | ≥2 万像素（1 / 3 下） | 传播 8 片后 |
|---|---|---|---|---|
| 现有「填充」点在空白上 | 0.07 | 0.07 | 0.15 | 0.08 |
| 删掉的旧智能填充（固定 256 窗口） | 0.68 | 0.81 | 0.50 / 0.82 | 0.76 |
| 只用随机游走（上一版） | 0.77（中位 0.92） | 0.82 | 0.63 / 0.79 | 0.78 |
| 只用标记分水岭 | 0.85（中位 0.94） | 0.88 | 0.79 / 0.84 | — |
| **两套择优（本版）** | **0.82（中位 0.94）** | **0.87** | **0.68 / 0.84** | **0.78** |

一片里已有标注少的时候（同样的留出切片，按标签编号随机留下一部分小细胞的标签，点 1 下）：

| 已有标注 | 只用随机游走 | 只用标记分水岭 | 两套择优 |
|---|---|---|---|
| 全部 | 0.77 | 0.85 | 0.82 |
| 一半 | 0.74 | 0.77 | 0.76 |
| 没有 | 0.74 | 0.43（122 次里 58 次填出真实细胞 3 倍以上） | 0.75（3 次） |

择优在每种情况下都不差于只用随机游走（标注齐全时点 1 下 +0.04、点 3 下 +0.05，自助法 95% 区间都不含 0），
也没有分水岭单用时的失控；代价是标注齐全时比只用分水岭低 0.03。调参切片上择优是 0.83 / 0.86（≥2 万像素 0.76 / 0.71）、
传播 8 片后 0.86；随机游走那套从调参的 0.80 掉到留出的 0.77，有轻微过拟合，分水岭从 0.82 升到 0.85。

已知弱点：两套都按局部暗度认膜，横穿整张图的暗条纹（切片 / 成像条带）会被当成膜，点一下可能只圈到两条条纹之间，
多点一两下即可；细长细胞贴着大细胞、中间的膜很淡时两套都会漏过去；补的点落在细胞核或膜上时可能比只点一下还差。

## 当前标签与新建标签

“当前标签”是下一次填充、画笔、种子分割或 SAM 应用使用的标签，不要求已经出现在当前切片；翻片保留选择。初始显示“未选择”，点背景不会改变选择。连续补标同一对象时，第一片新建一次，后续每片重新确定边界并点种子分割的“沿用当前标签”，就会使用同一个 ID 和颜色。种子预览后的“从邻片选颜色”提供前后各 2 片的重叠候选，点选只取色，不自动填色；换块或刷新后需重新选标签。
“新建标签”（N）分配块内未使用的 ID，跳过与当前片已有标签及本块新建标签相同的 RGB 颜色，并立即选中、高亮列表行。未涂色时没有图像区域可高亮。
“本片分段”分为“新建标签”和“已有标签”两组，分别列出本块所有新建标签及当前片的其他标签，搜索同时过滤两组。新建标签涂色后仍留在“新建标签”组，不重复列入“已有标签”；尚未使用的显示“未使用”，可跨片复用，不会自动涂色。
点击“新建标签”或“已有标签”列表行，会以黄色高亮选中行和本片该标签的所有区域；鼠标移开后仍保留，Esc、翻片、切块或选择另一项时取消。
`POST /new-id?z=<当前切片>` 返回字符串 `id` 及本块 `created_ids`；切片标签表也返回 `created_ids`，与像素索引表分开，避免影响像素统计。
新建记录保存在工作目录 `created_labels.json`，刷新或重启后仍可选择；不创建像素编辑记录，撤销涂色也保留该标签。标签 ID 是身份，颜色仍按 ID 稳定生成。

## 改动怎么落盘

原始 `seg.npy` 永远不动。第一次改动时把它整体复制为 `seg_edit.npy`（写时复制，839 MB 的块约几秒，只发生一次），
之后所有改动都写在副本上。每次改动另存一份 `edits/<n>.npz`——被改的每个体素的 (x, y, z) 坐标和它改动前的 id——所以撤销是精确
还原而不是"再填回去"（填充可能已把两个区域并成一个，反向泛洪会改错）。`edits.jsonl` 是给界面看的摘要。

交付给下游时使用工作目录里的 `seg_edit.npy`，它和 `seg.npy` 同形同类型。编辑副本、撤销记录与 `created_labels.json` 都是工作成果，应一同保留；回退标注使用撤销操作。

## 本片历史与提示

“本片历史”的计数、“本片改动”列表和撤销（Ctrl/⌘+Z）都以当前切片为单位，翻片自动更新。操作提示显示在右侧栏，可关闭，不覆盖图像。
点击“本片改动”的记录，会高亮选中行与该笔改动的准确像素区域（含已擦除位置），不改变当前画笔标签、不写数据；Esc、翻片、切块、撤销或选择另一项时清除高亮。
`GET /blocks/{b}/edits/{n}/mask.png?z=0` 返回只读高亮 PNG；历史跨片记录仅显示指定切片。
`GET /blocks/{b}/edits?z=0` 先筛选本片，再取最近记录；像素数也只统计本片。
`POST /blocks/{b}/undo?z=0` 仅撤销本片最近一次改动。历史整块操作只回退其中本片的像素，保留其他切片的记录、结果及溯源；旧记录无需迁移。
脚本接口不传 `z` 时仍返回整块历史、撤销整块最近一次操作。没有本片历史时不会改动其他切片。

## 前后对比与溯源

从工作台右上角「前后对比」进入 `/annotate/compare?block=<block_id>&z=<切片号>`，保留当前数据块与切片。
左图叠加原始 `seg.npy`，右图叠加当前 `seg_edit.npy`（尚未编辑时与原始相同）。两边共享标签配色、透明度、
缩放、滚动位置和光标，支持修改区域高亮；右图还可按来源着色。页面只读取数据；点击「刷新当前结果」获取其他页面的新修改。

报表按**当前像素的最后一次有效写入**汇总，再按标签 ID 统计。同一 ID 可以同时包含多种来源：

| 来源键 | 含义 |
| --- | --- |
| `baseline` | 原始分割中未被有效编辑覆盖的部分，不推断为人工真值 |
| `manual` | 画笔、橡皮、填充、清除、合并；兼容历史切割、分离记录 |
| `sam` | SAM 应用；基线 `meta.json` 含非空 `sam` 配置的非背景区域；或 `sam_merge.first_new_id/n_new_ids` 明确记录的预填 ID 范围 |
| `interpolation` | 历史插值记录，保留 `source_sections` 参考层号；不再提供生成此类记录的功能 |
| `assisted` | 算法辅助：种子分割（`seed`）、大块填充（`bigfill`）、边缘修缮（`refine`，点一下把压过膜的标签收回到膜）；以及历史智能填充记录（工具已移除，分类保留以便溯源） |
| `unknown` | 工作副本中无对应记录的修改、未知工具、缺失/损坏记录或当前像素与记录不符 |

人工点击「应用」SAM 或插值预览仍归相应算法来源；之后人工改写的像素归人工。来源不表示人工审核状态。
撤销后按剩余有效记录重新计算；这里不是包含已撤销操作的永久审计日志。旧记录没有 `source` 字段时按 `kind`
识别，新记录同时写 `source` 和 `provenance_version: 1`。历史切割记录若保存了逐像素新标签，可继续核实；旧版多块切割若只记了一个新 ID，
无法精确核实时显示来源不明。基线和历史编辑文件均无需迁移；对比专用的数据块列表和读取入口会在原位置读取旧工作文件，
不会触发标注工作台的历史迁移逻辑。工作台与对比读取在同一进程内共享数据块锁。

报表包含来源像素数、各标签前后像素数、混合来源标记，以及有效操作和缺失证据提示。`changed_px` 是与原始分割
不同的像素数；逐标签行中的该字段只计**当前归属该 ID**的变化，旧 ID 的减少体现在 `before_px/current_px`。
标签 0 表示背景，人工擦除也可追溯；顶部来源卡片只计非背景标签，JSON 另列 `background_pixels`。
JSON 中所有标签 ID 均为字符串，CSV 保留完整十进制值；用电子表格打开 CSV 时应将 `label_id` 列按文本导入。

页面可下载当前切片或整个块的 JSON / CSV。当前切片导出与屏幕快照一致；整块导出在请求时重新读取，
逐切片处理以避免加载整块 uint64 数组。`compare` 返回的图片与报表在同一数据块锁下读取，并禁用 HTTP 缓存。
该锁仅在当前服务进程内有效，沿用现有单进程标注工作流；不提供跨进程的并发编辑保护。

## 登录 · 谁改的 · 多人同时标注

标注工作区有**登录系统**（参照 CVAT / Label Studio 的做法：账号 + 角色 + 服务端会话）。账号和会话存在平台已有的 MySQL 里
（`users`、`auth_sessions` 两张表，启动时自动建）；密码用 bcrypt 存；Cookie 里是随机会话令牌（HttpOnly、SameSite=Lax），
库里只存它的哈希，14 天滑动过期（`EMQC_SESSION_DAYS`）。**全站**都要先登录——标注工作区、数据清洗工作区、数据下载、
QC 结果图（`/previews`）、接口文档（`/docs`、`/openapi.json`）都一样：页面跳到 `/login`，接口返回 401 `{"code":"auth"}`。
不登录能打开的只有登录页和它用的静态文件、`/api/v1/auth/login|status|logout|me`、探活 `/api/v1/health`（不报任何路径）、
前端报错上报 `/api/v1/logs/client`。关卡在 `app.py` 的中间件里（`auth.gate`），所以挂载的静态目录也管得到。

数据清洗那边按角色放行：**看**（列表、详情、切片、下载）登录就行；**跑任务**（QC、导出、爬取、patch 集、流会话、扫描、
改数据集元信息、登记资产 / 版本）要审核员以上；**删**（数据集、patch 集）只有管理员能做。训练 / 推理脚本不走浏览器登录：
服务器设 `EMQC_API_TOKEN`，脚本把同一个值放进环境变量 `EMQC_API_TOKEN`（`emqc.loader` 会自动带上请求头 `X-EMQC-Token`）；
令牌相当于审核员——能读数据、跑任务，不能改标注（标注必须记在真人名下）、不能删东西、不能管账号。没设令牌时这条路是关的。

角色三种：**管理员** admin（管账号、什么都能做）、**审核员** reviewer（能改、能撤别人的改动）、**标注员** annotator
（能改，只能撤自己的）。账号只停用不删除——旧记录里的 `by_id` 还要能对回人。第一个管理员在服务器上用命令行建：

```
python -m emqc create-user --username <登录名> --display <显示名> --role admin      # 交互输密码；留空则生成初始密码
python -m emqc users                                                             # 列出账号
python -m emqc reset-password --username <登录名>                                 # 发新的初始密码，踢掉所有登录
```

之后管理员在页面右上角「用户管理」（`/annotate/users`）建号：可以指定密码，也可以让系统生成**初始密码**（只显示一次），
拿初始密码登录的人会被先送到「账号」页改密码，改完才能进工作台。改密码后其它浏览器里的登录全部退出。登录连续错 5 次
（同一登录名，或同一个非本机的来源 IP）要等 60 秒。经 SSH 隧道进来的人来源都是 127.0.0.1，所以本机地址不按 IP 计数，
免得一个人输错几次就把所有人锁在外面；客户端自己填的 `X-Forwarded-For` 一律不信（前面没有反向代理）。

数据库短暂连不上（重启、卡住）时，最近 10 分钟内验过的登录继续有效，标注照常写文件；没验过的会话照样拒绝。
所有数据库连接有超时（连接 5 秒、读写 30 秒、取连接 10 秒），不会把工作线程挂死。

**试用模式（默认开）**：登录页照常，但不校验密码——填个名字就进（中文名也行，会当显示名，登录名由它的哈希生成），
账号不存在就自动建成标注员（`EMQC_AUTH_OPEN_ROLE`），停用的账号仍然进不来；管理员和设了真正密码的账号在试用模式下也要输密码。
自动建号一小时最多 30 个，再多请管理员在「用户管理」里批量建。内部使用、账号还没发齐的阶段就这样用；**正式开标前**在
「用户管理」先点「给他们各发一个初始密码」，把密码交给本人，再点「切到正式」（或设 `EMQC_AUTH_OPEN=0` 重启）——在这之前，
任何人填别人的名字都能以别人的身份操作。期间的改动记录不受影响。

**标注人**因此就是登录用户：每一笔写入（填充、画笔、橡皮、合并、批量删除、SAM 应用、撤销）由服务端按会话记
`by`（显示名）、`by_user`（登录名）、`by_id`（用户 id）——页面传什么名字都不认。`EMQC_AUTH_DISABLED=1` 关掉登录时
（本地开发、测试）退回旧方式：页面右上角填名字、随请求带 `annotator`；这时 `EMQC_ANNOTATE_REQUIRE_ANNOTATOR=1` 可以让不带
名字的写入返回 422，脚本照旧能用（`by` 记为 null）。

在哪里看得到：工作台「本片改动」每行末尾是谁改的，上方一行「改动人：张三 ×3 · 李四 ×1」；前后对比页「改了哪些地方」每处
标注人、鼠标读数里当前像素最后是谁写的（`editors_png` 索引图）、有效编辑记录表的标注人列、逐标签导出的 `editors` 列
（`张三:120;李四:30`）、`/blocks` 列表里每块的 `editors` 与 `last_edit`。

`audit.jsonl` 是**只追加的操作流水**：每一笔写入和每一次撤销，带流水号 `seq`、时间、标注人；撤销行另记 `of`（被撤掉那一笔的
标注人）和 `forced`。`edits.jsonl` 只保留当前有效的记录，被撤销的会消失，而"谁在几点撤了谁的"正是追溯要问的。对比页
「操作流水（含已撤销）」读它，接口是 `GET /blocks/{b}/audit?z=`。

**多人同时改同一张图**怎么处理（都在同一个服务进程里完成，写入本身由块级锁串行，不会把文件写坏；要解决的是"对着旧画面下手"）：

1. **切片版本号**。每一片的 `rev` 是最后一次动过它的操作（写入或撤销）的 `seq`，随 `labels/{z}.json` 下发（版本号在标签表之前、
   同一把锁里取，页面也先取表再取索引图，所以画面至多比版本号新、绝不会比它旧），只增不减
   （改动次数会在撤销后退回去，察觉不到"B 撤了一笔、A 又补了一笔"）。写入时页面带上自己看到的 `expect_rev`；服务端发现
   在这之后**别人**动过这一片，就拒绝（409 `stale`），页面自动重载这一片并提示"李四 在 14:02 改了 1,234 像素，请再操作一次"。
   自己的后续操作不算冲突——连续几笔涂抹到服务端比页面重载快。不带 `expect_rev` 或不带名字的调用（脚本）不检查。
2. **只能撤销自己的**。撤销永远撤本片最近一笔，多人时最近一笔可能是别人刚做的。撞上别人的记录返回 409 `not_yours`
   （带 `can_override`）：审核员 / 管理员的页面弹确认框说明是谁几点改的，确认后带 `force` 和确认时看到的记录号 `n` 再撤——
   中间又多了一笔就 409 `stale`，不会撤错；流水里记 `forced: true`。标注员只能得到提示（带 `force` 返回 403）。
   不允许"跳过别人那笔撤我上一笔"：记录里存的是改动前的旧值，别人后来在同一些像素上写过的话，回填旧值会把他的改动一起冲掉。
3. **同块在线**。工作台每 15 秒 `POST /blocks/{b}/presence {z}`，换回同块还有谁、在哪一片（按用户 id 记，只在内存里，
   60 秒没心跳算离线），右栏「本片历史」下显示「同块在线：李四（也在本片！）· 王五（z 12）」；同时比对这一片的版本号，别人改了
   就自动重载并提示。SAM 预览的过期判断也改为按片：别人改了别的片，不会让你的预览作废。
4. **一个工作目录只能一个服务进程写**。第一次写入时用 `flock` 占住 `<workdir>/.server.lock`（进程退出自动释放）；第二个
   进程写同一目录会得到明确报错，而不是两份进程互相看不见对方的改动、`edits.jsonl` 穿插着写坏。多人标注请都连到同一个服务；
   确实要再起一个服务，给它另一个 `EMQC_ANNOTATE_WORKDIR`。

建议的分工仍然是按块或按 z 段分，冲突检测是兜底而不是协作方式：两个人真的同时在一片上画，谁后提交谁重来。

## 上线运维：落盘顺序、磁盘、备份、接入

**写入顺序**。每一笔写入（填充、画笔、橡皮、合并、批量删除、修缮、SAM 应用）都是：算出要改哪些像素和它们的旧值 →
写 `edits/<n>.npz`（落盘）→ 追加 `edits.jsonl` → 追加 `audit.jsonl` → 才写像素。任何一步失败（磁盘满、进程被杀），
都不会出现"像素改了却没有记录"——那种改动撤不掉、也查不到是谁改的；记录那三步中后一步失败，前一步会撤回。两份日志都是
只追加的：追加断在半路留下的半行，读的时候忽略、下次追加前切掉；中间坏了（被人改过）则拒绝读取。

**撤销**。先回填像素（做多少遍结果都一样），再用 `.part` + 改名整体替换 `edits.jsonl`——这一步是提交点；之后才把这一笔的
像素文件挪进 `edits/undone/`（不删，误撤、事后追查都找得到；只撤了多片记录中的一片时，原文件在那里留一份，剩下的部分换上去）。
提交之前失败：日志和像素文件都原封不动，再点一次撤销会选中同一笔接着做完；提交之后的收尾失败只记日志，撤销照常算成功，
不会让人误以为没撤、再点一次把更早的一笔也撤掉。像素文件坏了，撤销返回 422 说明是哪一笔，而不是 500。

**磁盘**。工作目录所在盘低于 `EMQC_ANNOTATE_MIN_FREE_MB`（默认 1024 MB）就拒绝写入并提示联系管理员；新块第一笔要复制
整份 `seg.npy`（1024²×100 的块约 800 MB），复制前另外检查够不够。复制用逐字节拷贝而不是稀疏文件：盘满时老老实实报错，
而不是写的时候进程收到 SIGBUS 直接死掉。低于 `EMQC_DISK_ALERT_GB`（默认 20 GB）每分钟告警一次，`/api/v1/health` 报
`degraded`。守护脚本拉起的服务只往 `serve.log` 写警告以上（那个文件不轮转），完整日志在会轮转的 `var/log/emqc.log`。

**资源上限**。画笔一笔最多 1 万个点、插值后 20 万步；整块溯源导出同时最多 2 份，而且逐片持锁（导出期间别人照常标）；
对比页预热一次最多 21 片、同时一个；SAM 只在拍这一片快照时占块锁，加载模型和推理时不占；大块下载同时最多 2 个；QC、导出、
爬取各自同时只跑一个，其余排队。线程池 100 个线程。

**备份**（每晚一次，保留 14 天）：

```
python scripts/backup.py <备份目录或 user@host:/path> --dump-bin <mariadb-dump 的路径>
# crontab -e，每天 03:30：
30 3 * * * cd <部署目录> && <python> scripts/backup.py /备份/emqc >> var/log/backup-cron.log 2>&1
```

每份备份是 `emqc-<时间>/`：`annotate/`（标注工作目录全份，没变的文件和上一份硬链接，不重复占空间）、`db.sql.gz`
（`mariadb-dump --single-transaction` 一致快照，不锁表）、`BACKUP.json`。先拷像素、后拷记录；每个块拷之前、拷完之后各看一眼
`edits.jsonl`、`audit.jsonl`，拷的过程中有人落笔或撤销（日志变了）就把这个块重拷，直到前后一致（最多 5 轮，不行就报错告警）。
数据库口令从 `EMQC_DB_URL` 读、写进只有自己能读的临时配置文件，不出现在命令行里。备份失败推告警。备份必须放在**另一块盘
或另一台机器**上。恢复：停服务，把 `annotate/<块>` 拷回工作目录；`gunzip -c db.sql.gz | mariadb <库名>`。

**标注员怎么接入**。不要把服务器账号的密码或私钥发给别人：每人一把自己的 SSH 公钥，在服务器账号的
`~/.ssh/authorized_keys` 里一人一行：

```
command="/bin/false",restrict,port-forwarding,permitopen="127.0.0.1:<端口>",permitlisten="127.0.0.1:1" ssh-ed25519 AAAA… 张三
```

`restrict` 只关掉转发、终端和 `~/.ssh/rc`，**不拦执行命令**——所以要 `command="/bin/false"`：连上来只能跑这一个什么都不做的
命令；`port-forwarding` 再把转发打开，`permitopen` 只允许转到平台这一个端口，`permitlisten` 把反向转发限死在一个没用的端口上。
标注员连接时要带 `-N`（不开会话，只转发）：`ssh -N -L 18791:127.0.0.1:<端口> <服务器账号>@<服务器>`，不带 `-N` 会立刻断开。
谁走了删掉他那一行即可。管理员自己的钥匙不加限制。配好之后在服务器上实测一遍：这把钥匙 `ssh <账号>@<服务器> id` 应当什么都
不输出就断开，`-N -L` 隧道能打开平台。还有一个小口子（远程 Unix socket 转发）要管理员在 `sshd_config` 里设
`AllowStreamLocalForwarding no`。长期看应该在服务器上开一个只对校内网 / Tailscale 开放的 HTTPS 端口加反向代理
（那时设 `EMQC_COOKIE_SECURE=1`，nginx 的 `proxy_read_timeout` 调到 180 秒以上——整块溯源导出要一分多钟）。

**爬取来源**。爬取接口只允许 `EMQC_CRAWL_ALLOWED_SOURCES`（默认 `gs://h01-release/`，`https://storage.googleapis.com/`
写法等价）下的地址，`file://` 和别的主机一律拒绝；输出目录不再由调用方指定（导出固定在 `EMQC_EXPORT_DIR`，爬取固定在
数据根目录的 cloud 项目下）；新数据集 id 只能用英文字母、数字和 `_ . -`。正式部署里 QC、导出、爬取不能带 `sync=true`
在请求线程里同步跑。

## 审核与入库

标注员在「审核进度」页（`/annotate/review`）按范围「标记完成」；审核员在前后对比页顶部逐片「通过 / 退回修改 / 撤销通过」，
结论钉在画面上这一片的内容哈希上（之后内容一变，通过自动作废、回到待审）；参与过某一片的人不能通过它（严格四眼原则）。
进度按批次（数据块所在的导入目录）汇总；通过的切片由审核员在审核进度页按批次「入库」，生成整批的只读版本 `<工作目录>/_releases/<批次>/v<N>/<块>/`。
规则、状态表、接口、版本文件格式见 [REVIEW.md](REVIEW.md)。

## 对比页的标记与评论

对比页开「📍 标记」后点标注后图上的位置，写一句话，就钉在那个体素 (block, z, x, y) 上：图上显示编号的图钉，
下方「标记与评论」列出本片（或整块）的标记，谁都能回复、标为已解决 / 重新打开，作者和管理员能删。「复制链接」得到
`/annotate/compare?block=…&z=…&mark=<id>`，同事打开就跳到那一片、定位到那个点，两栏 Neuroglancer 也居中到该点。
标记存在 MySQL（`annot_marks` / `annot_mark_comments`），带作者账号、时间、钉下去时光标下的标签 id。

给 AI agent 用的是同一套接口（先登录拿到会话 Cookie，或将来发 token）：
`GET /blocks/{b}/marks` 读标记与线程，`POST /marks/{id}/comments {text, kind: "agent"}` 回复（界面上打「AI」标），
`PATCH /marks/{id} {status}` 标为已解决。每条标记都带 `label_id`、坐标和链接，agent 可以直接定位到图上去看。

## 已知限制

- 单片最多 65535 个 id（uint16 索引）；H01 一片几百到几千，够用。
- 页面上的填充、涂抹、合并、清除都是二维的，只改当前这一片。三维分裂（把错并的细胞在整个块里拆开）还没做。
- 3D：点击“看这一点”后在图像上选位置，或悬停时按 U；“看整块”直接打开块范围。活动按钮高亮，再次点击同一按钮（或再按 U）、Esc、切换工具/切片/数据块会取消并关闭本次打开的查看器；加载中的旧响应也会丢弃。位置换算成数据集体素坐标后交给公开的 H01 Neuroglancer。块的 `meta.json` 里 `geometry.origin` 是 mip1 体素单位，而查看器的默认坐标系正是 8/8/33 nm，所以直接相加即可，象限块再加上 `offset_in_parent`。只有本平台**没有改过号**的 id 才会传给查看器选中——SAM 预填和「新建标签」造的号在公开的 c3 分割里不存在，传过去会选中无关的细胞，所以被挡掉并给出说明。非 H01 数据块不给链接，只说明原因。
- 多人并发只到「按切片版本号拒绝对着旧画面的写入 + 只能撤自己的」这一层，服务端不合并两个人的意图：真的同时在一片上画，后提交的重来（见「登录 · 谁改的 · 多人同时标注」）。

## 回归验证

默认 `python -m pytest tests -q` 覆盖标注接口、两两合并、其他同标签区域与切片保持不变、精确撤销及原始标签保护。

真实浏览器交互测试单独启用，使用本机 Chromium 和独立合成数据：

```bash
EMQC_BROWSER_TESTS=1 python -m pytest tests/test_annotate_browser.py -q
```

需安装 `google-chrome` 或 `chromium`，以及 `websockets`（已包含于 `uvicorn[standard]`）。
如果临时目录路径过长，设置 `CHROME_TMPDIR` 为较短的可写临时目录，避免 Chromium Unix socket 路径长度限制。
浏览器测试不连接真实标注数据；无浏览器的环境可以运行默认接口回归。

## 右键菜单与左栏折叠（2026-10-28）

- **右键菜单**：在图上右键点一下（按下到松开移动不超过 4 屏幕像素）弹出菜单，对光标下这一块做四件事：拾取并高亮这个颜色、用当前标签填充、清除这块、修缮边缘。实现上分别调用 `setCur(id, true)`、`fill`、`fill(…, clearing)`、`refineAt`。拾取和点右栏标签行相同：换当前标签，并把这个标签在本片的所有碎片描成黄色（Esc、翻片、换块或再选别的标签时清除），不写数据；这块已经是当前标签时也可以点，用来看它在本片还有哪些碎片。其余三项和对应工具点一下完全相同，走同样的接口和撤销记录。右键拖动不弹菜单：画笔、橡皮下是擦当前颜色，其他工具下是平移。菜单开着时：↑ ↓ / Tab 选、Enter 执行、Esc 关；空格、其他键和左键点图只关菜单（左键这一下不执行工具）。翻片、换块、滚轮、切走窗口都会关菜单；菜单打开后这块被改过（同事改动刷新）或换了切片，这次菜单作废。种子工具下执行填充、清除、修缮会先退出种子工具。
- **左栏折叠**：「种子分割」「大块填充」「3D」默认收起（`<details>`），点标题展开。标注员自己点开或收起的状态记在浏览器 `localStorage` 的 `emqc.annotate.folds`；选种子工具、按 W、按 U 时自动展开，自动展开不记。正在用某个折叠区里的工具时把它收起，会退回拾取工具（3D 会取消，和 SAM 面板的做法一致）。数据块完整名字、尺寸、体素大小不再单独占一行，放在「数据块」下拉框的悬停提示里。
