# 切片填色：现在怎么做的，有了 SAM 之后怎么做

写给接手标注工作和接手这部分代码的人。上半部分讲现在的实现，下半部分讲拿到 SAM 分割结果之后推荐的流程，最后是交付约定。
文中的数字都是在 `h01_b0000_demo_data` 这个块上实测的，不是估计。

## 一、约定

一个**数据块**是一个目录，里面三个文件：

```
em.npy    (行, 列, z) uint8    电镜灰度
seg.npy   (行, 列, z) uint64   标签，0 表示未标注
meta.json                      体素尺寸、原点、来源
```

一张切片是 `arr[:, :, z].T`——数组的第 0 维是体数据的 X、第 1 维是 Y，转置之后屏幕的横轴才是 X、纵轴才是 Y，
和 Neuroglancer 对得上（见 [ANNOTATE.md](ANNOTATE.md)）。下面所有的行列都按显示后的方向说。
屏幕坐标是 `x = 列`、`y = 行`，落到数组上是 `plane[y, x]`。这条弄反过一次，导致浏览器缓存了方向错误的图，后来给电镜切片加了 ETag 和版本参数才根治。

**标签就是一张 id 图**，没有别的含义。同一个细胞在相邻切片上用同一个 id，颜色是 id 哈希出来的，所以同一个 id 在任何切片、任何块里都是同一个颜色。H01 的 id 超过了 2^53，JSON 里当数字会掉精度，所以接口上 id 一律是字符串。

## 二、当前填色的实现

分三层，每层解决一个问题。

### 第一层：浏览器里的索引图

每翻到一片，前端拉三样东西：电镜 PNG、**标签索引图** PNG、索引到 id 的对照表。

索引图是把这一片里出现的 id 重新编号成 0..k 存进一张无损 RGB PNG（R 放高字节、G 放低字节，合起来是一个 uint16）。这样做的原因是浏览器没法直接处理 64 位整数图，而一张切片里的 id 数量通常只有几百个，用 16 位索引足够。

有了这张索引图，**吸色、鼠标悬停高亮、连通块查找全在浏览器本地算，不走网络**。悬停高亮用的是扫描线泛洪，只缓存当前指着的和选中的两个区域，所以 1024² 的切片上移动鼠标也不卡。

### 第二层：服务端的写时复制

**数据目录是只读的。** 第一次改动时把 `seg.npy` 分块复制成工作目录里的 `seg_edit.npy`，之后所有写入都落在这个副本上，交付目录一个字节都不会多。分块复制是为了避免 800 MB 的体数据在内存里同时存在两份。

工作目录由 `EMQC_ANNOTATE_WORKDIR` 指定，默认 `var/annotate/<block_id>/`：

```
seg_edit.npy      工作副本，形状和 dtype 与原始 seg.npy 相同
edits/000001.npz  每次改动的像素坐标与改动前的 id
edits.jsonl       每次改动的摘要，页面右栏读它
```

### 第三层：逐像素的撤销记录

每次改动都把**被改动的每一个像素的旧 id** 存进一个 npz。撤销时把这些像素写回去，所以撤销是精确的，不是近似回滚。一次跨 100 片、上百万像素的整块合并也能一次撤销干净。

代价是磁盘：一次大合并的 npz 有 79 KB，一次普通填充 1.5 KB 左右。可以接受。

### 乐观更新

填充和涂抹是**先改浏览器里的索引图、立刻重绘，再把请求发给服务端**，失败了才回滚并重新拉这一片。所以点下去是立刻出颜色的，不等网络。

合并目前还是同步的：点完第二块要等服务端返回并重新下载解码这一片的标签图才解锁，一小时几百对的话会累积几分钟空等。这一条已经列进待改项。

## 三、现有工具

按"改的是什么"分成三类。

### 依赖已有标签的

| 工具 | 做什么 | 算法 |
|---|---|---|
| 拾取 | 取光标下的 id 作为当前标签 | 查索引图 |
| 填充 | 点到的连通块改成当前标签 | 在 `seg` 上按 4 连通取连通块；Shift 点击则改整片同 id |
| 合并 | 先点 A 再点 B，B 那块变成 A 的 id | 在服务端锁内重新读两个 id，避免前端缓存过期选错保留方 |
| 分离 | 把点到的块从同色不相连的块里分出来 | 连通块标记，取点中的那块给新 id |
| 切割 | 画一条线把连在一起的两个细胞切开 | 线栅格化成 8 连通细线当墙，对 4 连通区域是完整屏障；切出的最大块保留原 id，其余各给新 id，线本身的像素按最近邻归给两侧 |
| 清除 | 把点到的块清成背景 0 | 就是 `new_id = 0` 的填充，但不改变当前标签，方便"清掉再重画" |

这类工具的共同弱点：**标签错了它们就跟着错**。标签漏了一块，填充就漫过去。

### 不依赖标签、看电镜本身的

**智能填充**是为了解决上面那个弱点加的。它不看 `seg`，只看 `em`：

1. 算一张膜概率图——暗度和梯度各取一部分，做闭运算封住 1 像素的缝
2. 从点击处在非膜像素里泛洪，4 连通，膜是墙
3. 把泛洪结果里封闭的洞填上（线粒体、细胞核这些细胞内的暗结构本来就属于这个细胞）
4. 膜像素按"离谁近归谁"分给两侧，共享的膜从中线劈开

三个参数：**边界灵敏度**（越高越早停在膜上）、**可改范围**（默认只改点到的那个颜色，最保守）、**最大半径**（膜有缺口时的兜底）。

**结果先预览不落笔**：服务端把掩膜暂存在内存里给一个令牌，前端画成橙色叠加层，确认后才写。令牌 15 分钟过期，期间标签被别的操作改过就拒绝应用，不会覆盖更新的结果。

**当前精度不够**。拿交付标签当标准量，从细胞最深处点进去，平均 IoU 只有 0.49，而且逐片差异极大（某些片 0.69，某些片 0.37）。原因是这批数据是蒙太奇拼接，片间和拼块间的对比度不均，而现在用的是全局百分位阈值。正在并行评测六种替代算法（局部对比度归一化、优先队列泛洪、测地距离、多尺度脊线检测、随机游走、标签先验），评测脚手架在 `scratchpad/eval_harness.py`，用同一批真实标签打分。**这个数字改进之前，智能填充应当当作"给一个候选区域再人工核对"，不要当成自动工具。**

### SAM 辅助

页面左栏那一节，按需点选或框选，只作用于当前这一片，默认只填未标注区域。加了"贴合膜边界"选项，会把掩膜越过细胞膜的部分裁掉、差一点到膜的补齐，用的是上面那套膜检测。

## 四、实测：这批数据上各条路线

在同一个 512² 象限块、50 片上测的。

**交付标签的现状**

| | 值 |
|---|---|
| 全块不同 id | 932 |
| 每片 id 数 | 340 |
| 每片覆盖率 | 68.4%（象限块 32.9%） |
| 每个 id 的碎块数 | 1.28 – 1.43 |

**SAM 相对交付标签的表现，按细胞大小分层**

| 交付细胞面积 | 数量 | 中位 IoU | IoU≥0.5 | 完全没找到 |
|---|---|---|---|---|
| 10000px 以上 | 52 | 0.963 | 88.5% | 0% |
| 3000–10000px | 249 | 0.904 | 73.9% | 15.7% |
| 1000–3000px | 558 | 0.585 | 51.1% | 42.5% |
| 500–1000px | 737 | 0.526 | 50.3% | 47.6% |
| 200–500px | 1084 | 0.000 | 31.1% | 64.4% |

**结论：SAM 在大结构上很准，在密集小结构上不行。** 三千像素以上的细胞它基本都能圈对，边界贴着膜走；五百像素以下的（占交付细胞的 40%，主要是轴突横截面）它漏掉 64%。

欠分割（一个掩膜吞掉多个细胞，最贵的错误）只占 1.8%，每片平均只需一次切割修正。过分割每片约四次合并。这两个代价都不高。

## 五、有了 SAM 之后推荐的填色流程

核心判断：**SAM 补空白，人管细节，两者不要互相覆盖。**

### 第一步：合成一个预填块

```bash
python scripts/merge_sam_masks.py raw_masks <源块目录>
```

这个脚本做四件事：

1. 每片把重叠的掩膜画成一张标签图，大的先画，一个像素只归一个掩膜——整个细胞会盖过 SAM 在它内部提出的细胞器掩膜
2. **保留交付标签，只在未标注区填 SAM**。压在已有标签上超过一半的掩膜整个丢弃（丢的是碎片，不是细胞）
3. 丢掉交集后不足 `--min-area`（默认 300 像素）的碎渣
4. 按重叠把 id 跨片连接，允许跨一片的断档，让同一个细胞尽量保持同一个颜色

输出是 `var/sam_blocks/<块名>_sam_filled/`，自动出现在标注页的下拉里。原块和掩膜目录都不会被写。

在这批数据上的实际效果：

| | 值 |
|---|---|
| 掩膜总数 | 2626 |
| 采纳 | 533 |
| 因压在已有标签上丢弃 | 1700 |
| 因太碎丢弃 | 393 |
| 新增 id | 190 |
| 覆盖率 | 32.9% → 60.9% |
| 耗时 | 43 秒 |

### 第二步：在预填块上按区域分工

打开预填块后，屏幕上有两种颜色来源，处理方式不同：

- **交付标签覆盖的区域**：这是人工结果，只做校对。用拾取看 id、合并修错分、切割修错并。
- **SAM 补上的区域**：这是机器猜测，重点检查边界和跨片一致性。大块基本可用；发现一个块横跨了两个细胞就用切割，发现一个细胞被切成几块就用合并。
- **两者都没覆盖的 39%**：用智能填充或 SAM 辅助按需补，或者画笔手工画。

### 第三步：跨片一致性是目前最大的短板

实测：SAM 补的 190 个 id 里，**54% 只出现在一片上，中位跨片长度是 1 片**，最长 29 片。翻页时这些区域的颜色会不停变。

原因不是连接阈值设得不对——相邻片之间 22.4% 的块在下一片根本没有任何重叠，SAM 压根没在那片提出这个物体。把阈值从 0.4 降到 0.2 只多连 5 个百分点，加上跨一片容错把单片占比从 61% 降到 54%，仅此而已。

**正确的解法是换推理方式**：SAM 2.1 自带视频模式，把 z 当时间轴做掩膜传播，天生就有跨帧一致的对象编号，不需要事后按重叠去猜。服务器上装的就是 SAM 2.1，代码里现在只用了 `SAM2ImagePredictor`，换成 `SAM2VideoPredictor` 即可。这是下一步最值得做的事，比继续调连接参数的收益大一个数量级。

在那之前，跨片不一致的区域建议这样处理：先在一片上把边界修对，再用整块合并（`/merge` 接口，`scope: block`）把相邻片上同一个细胞的不同 id 并成一个。

### 什么时候不要用 SAM 预填

**已有可信标签的块，不要整块替换成 SAM 的结果。** 它的 id 是另一套编号，和交付的对不上，改完并不回去；而且在密集小结构区它比人工标注差。上面的脚本默认就是保留交付标签的，`--overwrite` 存在但不要用，除非源块本来就没有标签。

## 六、交付说明

### 标注结果在哪里

修好的标签是工作目录里的 `seg_edit.npy`，形状和 dtype 与原始 `seg.npy` 相同，可以直接 `np.load`。没有产生过改动的块不会有这个文件，这时用原始 `seg.npy`。

```
var/annotate/<block_id>/seg_edit.npy      ← 这个就是结果
var/annotate/<block_id>/edits/*.npz       ← 逐次改动的像素级记录
var/annotate/<block_id>/edits.jsonl       ← 改动摘要（谁、什么操作、多少像素、什么时候）
```

`edits.jsonl` 每行一条，字段固定：`n` 序号、`kind` 操作类型、`z` 切片（整块操作为 null）、`n_px` 像素数、`old_id` / `new_id`、`ts` 时间。审计和统计工作量都读它。

### id 空间

- **交付原有的 id** 保持不变，不要重新编号，否则没法和上游对上。
- **页面新建的 id** 是当前块最大 id + 1 递增。
- **SAM 预填的 id** 从交付最大 id + 1 开始，所以看 id 的大小就能区分是人工的还是机器补的，`meta.json` 里 `sam_merge.first_new_id` 记着分界线。

### 接口

脚本化处理走这些，语义和页面上的按钮完全一致：

```
POST /api/v1/annotate/blocks/{b}/fill                 {z,x,y,new_id,whole_slice}
POST /api/v1/annotate/blocks/{b}/paint                {z,points,radius,new_id}
POST /api/v1/annotate/blocks/{b}/merge-pair           {z,first:[x,y],second:[x,y]}
POST /api/v1/annotate/blocks/{b}/merge                {from_id,to_id,scope:block|slice,z}
POST /api/v1/annotate/blocks/{b}/split                {z,x,y}
POST /api/v1/annotate/blocks/{b}/cut                  {z,points}
POST /api/v1/annotate/blocks/{b}/smart-fill/preview   {z,x,y,sensitivity,max_radius,scope} → 掩膜 + token
POST /api/v1/annotate/blocks/{b}/smart-fill/apply     {token,new_id}
POST /api/v1/annotate/blocks/{b}/sam/predict          {z,points,labels,box,only_background,snap_boundary}
POST /api/v1/annotate/blocks/{b}/sam/apply            {token,new_id}
POST /api/v1/annotate/blocks/{b}/undo
```

所有写操作都返回改动记录和当前改动总数，都能撤销。

### 环境变量

```
EMQC_ANNOTATE_ROOT          数据根目录（只读）
EMQC_ANNOTATE_EXTRA_ROOTS   追加的根目录，分号分隔
EMQC_ANNOTATE_WORKDIR       工作目录，默认 var/annotate
EMQC_SAM_BLOCKS_DIR         SAM 预填块目录，默认 var/sam_blocks，自动出现在下拉里
EMQC_SAM_CHECKPOINT         SAM 2.1 权重
EMQC_SAM_DEVICE             默认 cuda:0
```

## 七、已知限制

- 填充、涂抹、合并、切割、分离、清除**都只改当前这一片**。三维操作只有按 id 的整块合并。把一个错并的细胞在整个块里拆开还没做。
- **没有多人并发控制**。同一个块同时开两个页面改，后写的覆盖先写的。多人标注要按块分工。
- **没有重做**。撤销会把改动记录删掉，多按一次就找不回来了。
- 智能填充的精度（平均 IoU 0.49）不够，算法替换中。
- SAM 预填的跨片一致性差，正确解法是改用 SAM 2 的视频传播。
- 页面没有登录和权限。服务端 `EMQC_ALLOW_DELETE_FILES=0` 时任何页面都删不了磁盘文件。
